## A 最终要得到什么

让 Agent 像读图片、文字一样读取视频。用户给链接、BV 号或本地文件，之后直接自然语言讨论。Agent 自己完成获取、阅读、核对、保存和必要的返读。

视频是原始媒介，笔记是可选产物。用户用自然语言提问，Agent 自己选择观察方式并取得足够证据。完整性按任务界定，同时减少无效读取；采样、定位和补看服务于这种体验。

当前收窄为“视频/链接 → Reader → 通用、按需披露、可回查的材料”，便于独立接入 CLI、MCP 和宿主薄插件。宿主可进一步生成文字或 HTML 图文笔记；0.10.0rc1 已实现无损交付契约与可移植导出。

Scroll 的账号推荐、偏好与日试用是独立消费方，保留已确认路线；其运行规则见[日试用说明](../docs/daily-trial.md)。它的长期收益不是 Reader 公开的前置条件。

2026-10-24 将仓库公开列为后续优化方向。先验证组合收益、守住职责与证据边界，再准备可独立复现的干净源码交付。它是对外复用的工作，不增加第三套阅读实现，也不要求先完成个性化推荐；计划与去重见 F 节。

自主运行的交付不新开聊天，只使用私信与本地记录。现有按链接阅读和自然语言讨论仍可使用；本开发会话也不属于自主推荐的交付产物。

| 已确定的原则 | 当前含义 |
|---|---|
| 阅读能力可被其他 Agent 复用 | 独立组件，提供 CLI、MCP 和宿主调用流程 |
| 平台适配可各自配置 | B 站处理 BV、分 P、账号与字幕；YouTube 保留独立配置 |
| 默认本地处理 | 本地抽帧、OCR、ASR；Gemini 默认关闭，无自动云端回退 |
| 完整性、准确性与读取消耗 | 先满足任务所需证据与清晰度，再减少无效获取、处理和重复读取；限制通过分批与准确续读处理 |
| 按需披露与完整续读 | 默认校对正文，原文、修改理由及证据可展开；全量材料保留可取得路径 |
| 独立保存 | 应用、配置、模型与缓存位于 D:/IA/apps/video-reader |
| 公共运行环境不自带 | Python、FFmpeg、Node 等按文档作为本机依赖 |

早期“以 BiliLearn 为底座”的[构想](../docs/刷视频agent-idea.md)保留为历史参考，当前采用独立 Reader / Scroll，不据此另起底座迁移。

## B 三块职责如何衔接

```flow
平台适配与独立账号 -> 通用视频阅读: 获取视频和字幕
用户主题 -> 基础搜索与热门发现: 已实现
基础搜索与热门发现 -> 通用视频阅读: 宿主选择候选
用户链接或BV号 -> 通用视频阅读
通用视频阅读 -> 宿主Agent: 时间戳画面与语音证据
宿主Agent -> 校对稿及证据缓存: 语境判断和忠实校对
校对稿及证据缓存 -> 自然语言讨论: 默认正文及按需证据
可选参数化唤醒 --> 推荐与选片模块: 已接通，仅首页首条日试用启用
推荐与选片模块 --> 通用视频阅读: 已复用正式组件
推荐与选片模块 --> 本地记录与单向私信: 已接通，按当前授权范围启用
用户反馈 --> 历史与偏好: 已保存真实反馈
历史与偏好 --> 推荐与选片模块: 长期收益待验证，自主探索待实现
```

这些是逻辑职责。当前 B 站账号代码仍位于 Video Reader 内，尚未抽成单独的平台服务。

组件负责获取、抽帧、字幕、ASR、OCR、复听和证据存取。宿主 Agent 负责理解语境、判断冲突及校对。组件没有额外运行一个校对语言模型。

Scroll Agent 已调用同一阅读能力。Reader 会话缓存复用视频材料；Scroll 另行维护兴趣、反馈和运行记录，二者不混为一种状态。

当前判断：核心链路已跑通，可继续日常试用并打磨可靠性。整体尚未达到“各种视频都能像读文字一样稳定理解”的终点。

对于已校对会话，分层返回已经工作。首次宿主校对仍要读足够的语境和相关画面；仅调用 open 或 transcript，不会凭空生成校对稿。

动态画面当前只检查显著数值或公式的局部变化。默认向后观察 10 秒，以 2fps 最多取 32 帧。它仅观察文字保持，不宣称动画语义已结束。缺少通用动作追踪、镜头/事件边界和声画同步语义；非常短的事件可能落在抽样间隔内。

原生声音当前明确返回 raw_sound_understood_by_host=false。ASR 和对齐只回答“可能说了什么、可能何时说”，没有独立的音乐/音效识别、韵律/说话人分段或连续声画联合读取。默认关闭的 Gemini 入口不算这项缺口已补齐。本轮新增的是本地声音测量，没有新增视听模型或云端上传。

## F 后续按什么顺序推进

### 本轮已确认并实施：材料接口同步（2026-10-26）

已接入组件登录下的 UP 主原生作品分页，复用固定 yt-dlp 签名/分页与共享 transport；支持 UID、空间链接或 BV。Reader 统一 preview 门面与 CLI/MCP，增加有界批量和密集分镜、时间标记拼图，优先已有完整缓存。

普通轻预览仍为默认；风格、剪辑或分镜比较由宿主按任务选密集模式。文档、Skill 与两端插件同步，保留原有阅读、语音及 Scroll 业务能力。验收和保全证据见 D 节，不将本轮有限宿主调用扩成完整语义阅读验收。

### 已确认的 Scroll 路线：继续日试用与反馈

#### 使用者要得到的体验

用户给出视频和问题，Agent 自己选择读取方式、取得足够证据并回答。用户不必决定取多少帧、用哪种采样或手动翻页。完整学习可以讨论全片；局部提问可以直接定位、核查并在必要时扩展上下文。追问能回到同一来源和校对版本，中断后能接着读。引用和保存的材料能够再次打开。

完整阅读同时衡量任务所需的完整性和取得证据的消耗。在满足完整性、准确性和必要清晰度的前提下，减少无效下载、处理、重复交付及宿主读取。完整性不由固定帧数、均匀取样或翻完预生成图片来定义。

所有正文、原始证据及必要图像仍须有完整取得路径。传输或上下文限制通过无损分页、拆图和稳定续读处理；不用摘要、截字或低清图片替代必要材料。任务需要继续观察时，不以预设 token 数或帧数宣告完成。实际资源限制须给出已完成范围、缺口和继续位置。

本轮先完成 Reader 工程更新与技术发布候选，再进行 Scroll 批量阅读调试。运行路径及依赖从开始就处理；各阶段是实施顺序，无需逐批重复请示。Reader 功能与技术候选已完成，Scroll 本轮已接入显式队列并完成真实批量调试；后置标签、自主探索不并入。

#### 第一阶段：任务驱动的读取与完整交付一起实现

先统一来源、修订与继续位置，再接入无损分页、图像精读和观察策略。同一案例须串通如何选证据、实际看清、读取完整及准确接续。

**自动选择下一步观察。** 复用平台元数据、preview、本地 ffprobe、字幕与转写、镜头候选、OCR 和区间缓存。宿主理解用户问题并选择观察重点；组件返回材料状态、选择依据和可执行的继续参数。不给每个视频另开一个理解模型，也不要求用户选择技术模式。

| 任务或材料 | 初始读取 | 继续观察与完成条件 |
|---|---|---|
| 有字幕的讲解、完整学习 | 读全选定语音来源，按操作、公式、图示指代与章节转折选图 | 结合贯穿时间轴的样本与画面变化检查，补查字幕没有说出的内容；完成必要画面核查与忠实校对 |
| 无字幕、以讲话为主 | 已有概览与已就绪转写先返回；初始可均匀取样 | 转写、镜头或文字变化出现后调整观察；中断补齐语音缺口，未取得字幕不能解释为无语音 |
| 剪辑、美术、动作或操作演示 | 以画面变化和时间顺序组织材料，字幕辅助定位 | 对短镜头、操作步骤和不清楚的运动过程局部加密；抽样不声明连续视听理解 |
| 具体事实或指定时刻 | 先取相关语音和精确时间帧 | 证据不足、上下文缺失或声画冲突时扩大区间；局部结论不扩为全片结论 |

“有字幕按需取帧、无字幕均匀取帧”是初始策略参考，不作为硬分支。字幕的有无不能决定视觉覆盖是否充分。保留时间轴样本和变化检查以发现字幕外的线索；它们仍不能证明没有遗漏短暂事件。明确动作类问题需要更密的观察或保留无法确认的边界。

默认阅读流程按任务选用均匀、镜头、文字变化、密集或精确时间读取。现有显式参数保持有效，轻预览仍保留轻量默认。密集分镜属于正式维护和回归范围，由任务触发。旧调用不会在未说明的情况下丢失约定材料。

底层已有 extract_scene_candidates、extract_scene_or_uniform 和定点抽帧。复用它们并记录实际帧时间、选择方式及缺口。概览可以比较候选清晰度，指定时间的原帧仍保留，稳定参考另附。静态代码一字符变化、公式变化、黑场和短镜头不能被默认为冗余。避免全局感知去重，不复制对照项目已知误切的 HSV 算法。选帧失败可披露原因并回到已有采样，不自动换云端、模型或语音来源。

**无损正文。** 复用段落、时间和来源字段，按实际返回量优先在内容边界分页。超长单段按原段内字符范围继续，保留原段 ID、原时间和顺序，不伪造词时。各页重组后须与同一快照逐字一致、顺序一致，正文不重不漏。重复的解释上下文与正文区分。reading、raw、evidence 均保留完整取得路径及来源关系。

**准确续读。** 连续读取固定源版本、分 P、账号域、请求范围、source/context/view、snapshot/revision 和位置。复用 session/read/frame ID、offset/page 与检查点。来源或修订变化时保留旧快照续读，或明确报告变化并重新定位；不把新内容混入旧分页。不要为统一引用强制轻预览下载完整视频。

**实际看清。** 拼图格子对应源身份、原帧、时间精度和局部读取入口。原生分镜保持近似标记，导航窗口不代表整窗已观察。小字、数字或公式难辨时，取原图、拆页或局部高清材料。以 Codex、Claude 实际收到的图片与识别结果校验，不能只检查本地图片尺寸。

**消耗与完成状态。** 分别记录下载/解码/ASR/OCR、交付文字与图片、宿主实际读取和调用消耗。沿用缓存和已审阅材料，减少重复处理与重复交付。源材料处理覆盖、交付范围、观察记录、校对状态和理解正确性继续分开。完整学习保持全量语音与忠实校对的现有体验，不擅自改成摘要或只核对少数疑点。

#### 第二阶段：长任务恢复、声音线索及平台验收

长任务复用既有区间检查点，先返回已经就绪的材料和继续位置，逐步补齐缺口。已有可用材料不必等待全片处理才可访问；部分结果必须明确适用范围。失败后继续未完成区间，不重新转写已完成部分。区分冷启动和缓存返读成本，不靠延长超时或提前标为读完替代体验改进。

基础声音线索纳入本轮：用已有 FFmpeg 测量响度、静音和突变，保留源时间，帮助定位补看或复听。它们不表示已识别音乐、音效、情绪或语气，也不能据此删除疑似语音。连续动作和原生声音语义研究继续保持既有边界。

验收覆盖 B 站、YouTube、本地视频以及中文、英文。平台公开素材及自造样本分别验证有字幕、无字幕、轨道选择和视觉信息。只有实际通过的组合列为已验证支持；外部平台受限要记录具体缺口，不能用本地测试替代在线通过。

YouTube 使用用户提供的 Cookie 文件。**已知取舍：采用手动导出与更新，登录失效后由用户重新提供。** 本轮不采用专用浏览器配置、自动提取浏览器凭据或自动维护登录会话。这样减少安装与运行依赖，但长期无人值守读取可能被凭据失效打断。自动维护只保留为未采用的备选，不作为本轮完成条件。

复用既有 cookies_file 入口，继续补登录状态判断、凭据变更后的缓存隔离、失效提示，以及进程重启和两端共用验证。维护范围收窄不降低阅读完整性和准确性。Cookie 原文不进入日志、输出材料或源码候选包；凭据失效明确报告，已有离线材料继续可用。导入开始和收尾分别检查实际登录证据，报告实测跨度；公开视频能下载不单独证明已登录，不承诺永久登录。

| 无字幕视频或受控中断后的续读 | 本地转写、已完成区间复用、缺口和失败可见；保持所选来源 | 继续读完所需分页，准确说明缺失、未确认和失败；不把超时或空输出判成已看完、无语音 |
| 系列筛选或视频用于一个示例项目 | 复用各视频材料、定位片段、保存来源；不内置用户知识画像 | 用公开 / 自造项目背景完成取舍，并引用具体证据。比较去重、跨项目推理和编排属于宿主，临时脚本须明确标示 |

2026-10-24 的 20 条系列导读及 BV1nGJ26JEuh 图文案例可作为组合能力的候选演示；后者已登记真实输出交付缺陷。20 条导读完成完整字幕与顺序抽帧、局部复核、总集篇比对，再结合授权项目背景选择片段。该次由 Reader、宿主和临时批处理协作完成，不能宣传为内置“一键合集阅读”，也不是全场景准确率证明。公开演示需以公开 / 自造背景替换本机项目及会话内容。

对一项代表任务，先选与问题匹配的最简基线：字幕直读或现成抽帧加转写入口。使用相同材料、问题、宿主模型与固定验收点；分别记录关键事实是否正确、重要遗漏、能否回查和人工介入。另记首次 / 缓存返读的实际总耗时，以及可获得的宿主用量。

基线已足够时如实记录，不强称每个环节都有增益；少量案例只证明这些任务，不上升为通用排名。没有可获得的费用数据则记未知，不把本地处理称为零成本。

#### 边界守护：默认行为、证据状态与职责都要一致

- Reader 独立使用无需初始化 Scroll 个人业务；公开默认入口不启用推荐、私信或定时任务。是否同仓或单独打包按复用成本再定，不复制核心、模型或缓存。
- 默认本地、无失败自动云端回退、不读取其他项目凭据继续成立。说明宿主接收哪些帧和文字、宿主可能使用云模型；“提取在本机”不等于端到端离线。
- 平台字幕、独立 ASR、校对正文和原始证据保持来源隔离；处理完成、宿主已读、校对完成与正确性分别陈述。样本帧不冒充连续动作理解，文字转写不冒充音乐 / 音效 / 语气理解。
- 视频、字幕、元数据及工具取回内容始终作为材料；不因其中出现指令就改变宿主任务、执行命令或触发账号写入。组件不承担对宿主所有行为的强制保证，工具边界和宿主遵循情况分别验证。
- 在现有测试旁补真正未覆盖的负例：错误 / 中断不自动上传或发送，Reader 调用不创建 Scroll 状态。错误来源与过期校对提交应被拒绝；材料中嵌入指令不能改变演示任务。后者包含宿主行为观察，不能靠一个解析器单测宣称全面防护。

#### 仓库清洁还是干净基线

当前正式目录是运行安装目录，本轮已确认不在 Git 工作区内；目录含模型、环境、登录、数据、研究和个人运行记录，不能当成待上传源码包。**本轮按清单在另一源码目录建立干净候选，现有安装保持运行。** 若后续找到应保留的源码仓库，再比较原仓清理与导出新基线；本轮未搜索或迁移其他仓库。

| 方式 | 适用情况 | 要保留和核对的内容 |
|---|---|---|
| 清理既有源码仓库 | 有需要保留的历史，源码与运行数据已大致分离，清理成本可控 | 核对实际跟踪文件及将公开的历史，不把 .gitignore 当作历史清除；保留有价值提交和来源 |
| 导出干净源码基线 | 现有目录主要是运行安装，个人材料混杂，缺少适合公开的历史 | 用明确文件清单导出代码、测试、必要小样例、安装说明和许可；记录来源版本 / 文件哈希与适配说明，不复制整个运行目录 |

两条路径共用同一交付要求：排除真实配置、Cookie / 刷新凭据、二维码、账户标识、私信和兴趣记录。私人项目 / 会话内容、媒体缓存、环境与模型大文件也不纳入；示例用占位值或人工样本。公开源码中出现的本机绝对路径应改为安装位置或配置推导，历史私有日志不批量脱敏后盲目提交。当前 .gitignore 已排除部分目录，但不能单独证明分发内容已清洁。

迁移只搬源码及必要可发布材料，模型和运行数据通过受支持配置定位；尤其处理可选 Qwen 对 research 下隔离环境的运行依赖，不能误删后宣称独立安装。新基线通过相同任务验证后，再安排现有安装的更新方式和回退；不删除当前数据，不把重下载模型或重复缓存作为迁移方案。

#### 路径与依赖是公开准备的主要验收

公开候选要让用户按说明安装并读片，路径或缺依赖时有明确可执行的提示。只有在原开发目录运行成功，不算完成。

| 场景 | 必须达到的结果 |
|---|---|
| 换盘符、中文/空格目录、其他工作目录启动 | 安装位置可变；相对路径有明确的配置或安装基准，不随当前目录漂移 |
| 源码、模型、凭据、缓存与配置 | 可用受支持配置定位；现有安装更新复用资源，不强制搬迁、复制或重新下载 |
| Python、FFmpeg/ffprobe、Node 和基础包 | 文档与安装入口覆盖实际必需依赖；查找与版本兼容可诊断，不借用未说明的开发环境 |
| ASR、Qwen、GPU 等可选部分 | 基础使用不被可选引擎缺失阻断；Qwen 独立环境有安装方式，解除默认 research 路径依赖并兼容现有配置 |
| Codex/Claude 薄插件 | 按实际安装根生成启动路径与使用说明；更新、重装后能调用同一核心 |
| 模型与网络准备 | 写清必要模型的取得和校验方式、离线运行条件及可选依赖；不把开发机已有模型当成新用户自然具备 |
| 干净安装与移位交付 | 在另一目录、新环境只按候选包说明完成读取、返读、恢复和导出；另测导出包脱离原缓存的引用 |

保留兼容声明并核对实际锁定依赖是否可取得；必要更新围绕具体失败及受影响平台验证，不顺便升级所有依赖。开发机缓存可加速安装，但不能掩盖遗漏的安装步骤。若只有本机隔离环境，就如实声明验证范围，不称为已在另一台机器或其他系统通过。

#### 首次使用、许可与维护的最小交付

1. **可复现安装。** 从干净目录验证声明支持的系统、宿主与依赖版本；移除用户专属路径。缺少 FFmpeg、模型或登录时给出可操作提示；可选 Qwen 单列依赖，基础使用不被它阻断。首批只支持已实测组合，未测平台和宿主明确列出。
2. **清楚的入口与示例。** README 先说明给谁用、三种任务示例、最短安装路径、材料去向和限制；开发史、私人运维记录与用户文档分开。普通读片无需了解 Scroll；批量脚本与外部 Agent 能力各自标注。
3. **明确分发范围与归属。** 复用现有许可复核和第三方声明；新代码对外许可证仍待选择。按实际分发的源码、模型、二进制和样例分别核对，保留 watch 等上游归属与修改说明。首版优先源码及依赖安装说明。其他资产是否随包分发另行决定，不重做已有许可盘点。
4. **能报告问题并复现修复。** 提供简短问题模板、无凭据诊断信息和最小贡献入口。列明支持范围、版本与更新 / 回退方式。现有测试按支持矩阵复用；公开 CI 不依赖私人账号、真实私信或本机媒体缓存，需登录的在线检查单独说明。

**建议次序与完成标准：** 先确定首批承诺的任务和边界，再选择清洁路径并做干净安装。最后用代表任务核对组合收益与实际发布清单。

让未参与开发的人只按公开说明安装并完成任务；也可先在隔离干净环境中验证。能装好、读片、回查并识别失败边界，才说明达到该窄范围公开候选基线。要宣称跨宿主或其他平台支持，就补相应实测；无需先做 GUI、SaaS、全面多平台、独立推荐模型或大规模盲测。

上述准备通过不自动触发远端创建或上传。发布时机、目标仓库与许可证届时明确；当支持声明、依赖或实际分发范围发生变化时补相关检查，通过后不为收尾反复扩测。
