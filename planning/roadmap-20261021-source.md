## A 最终要得到什么

让现有 Agent 像读图片、文字一样使用视频。用户给链接、BV、本地文件或主题，可以先看再聊，也可以带着问题深入。笔记是可选产物，Reader 提供通用、可继续读取、可回查的材料。

完整性、准确性、响应速度与成本共同服务于这个体验。已足以回答与全部内容已核查可以分开。优先复用已有材料，主动核查影响当前答案的疑点，及时回答并保留其余未核查内容。不截断必要正文、不降低必要清晰度，不把未核查内容写成定论。

Reader / Scroll 分工、默认本地及公开准备边界继续保留。Reader 初校机制仍待讨论；Scroll 已完成状态、Inbox/队列和显式粗读原型，后台消费尚未接入。两者分开，不因旧路线有待办就自动扩展功能。

## B 当前职责与目标差距

```flow
用户需求或开放阅读 -> 宿主Agent
宿主Agent -> Reader: 获取、定位、续读与补证
Reader -> 宿主Agent: 图像、语音文字、差异和来源
宿主Agent -> Reader: 语义修正与未解决疑点
Reader -> 可复用材料: 原文、校对、证据和修订
可复用材料 -> 宿主Agent: 后续直接读取
宿主Agent -> 用户: 理解、讨论与所需产物
Scroll个人工作流 -> 通用任务与记录: 收件引用与结果
宿主Agent -> 通用任务与记录: 手动任务、历史与结果
通用任务与记录 -> Reader: 复用公开材料接口
```

Reader 已承担平台适配、登录、字幕/ASR、取帧、OCR 差异、局部复听、缓存、分页与导出。语义校对仍由宿主负责；复听和 OCR 返回候选，不自动覆盖原文。`review` 负责准备材料和保存提交，并不另跑校对语言模型。

已有校对稿可直接复用；首次读取没有自动生成语义初校稿。源码 Skill、MCP 与生成薄适配器已同步及时回答；默认阅读只复用已有核验，新 OCR 按需请求。Reader 独立初校是待验证方向，不能把材料整理或疑点检测写成校对已经完成。

adaptive 利用字幕时间、场景变化与时间线检查选初始帧。任务文字由宿主解释，组件自身不按问题语义找齐证据；后续定位、补帧和裁切由宿主选择。

## C 当前完成到哪一步

核心 0.10.0rc6，薄插件 0.5.5；Reader 20 工具、Scroll 7 工具。2026-11-04 新增 scroll_inbox / scroll_queue，负责显式收件、待办与历史；另有显式 scroll_triage 轻预览及宿主判断原型，不随同步自动触发。此前评论/楼中楼分页、按分 P 分段弹幕及同段冻结续读沿用组件登录与限流；不承诺隐藏/删除或历史全量内容，特殊弹幕专包和互动弹幕未纳入。

## F 后续讨论与候选方向

### 1. Reader 初校与回答时机

Reader 分支仍需把初校职责和回答时机确定清楚。用户不需要重复确认已说明的目的；执行者应基于既有样本说明可行范围，再讨论会改变体验或责任的取舍。本次文档维护不授权启动新模型或自动初校开发。

需确定的机制包括：Reader 独立承担哪些基础处理；首次材料未准备好时怎样及时给出有依据的回答；哪些疑点现在查、哪些保留；宿主何时需要提交校对。旧 Skill 的完整语境要求与 API 的处理范围约束应分清，不能只改话术就声称等待减少。

### 2. 已有改进方向合并进入验证

以下是讨论后的候选验证内容，不是本轮已开始实施的清单：

| 方向 | 复用与判断依据 |
|---|---|
| 基础初校与疑点定位 | 复用现有字幕、ASR/OCR 差异和局部复听；测正确修正、误改、关键漏报，保留原文和来源，不把一致性或无警告当正确性 |
| 连续字幕阅读视图 | 复用长访谈和 Scroll 重复样本；保留原始条目、时间、段 ID 和修订，不按长度删句。原先单列的优先项并入响应体验验证，避免先定实现次序 |
| 回答时机与宿主流程 | 比较首次准备、疑点补查、首个可用回答及后续追问时间；允许明确的未核查内容，不以固定秒数/帧数压低必要质量 |
| 跨会话继续深入 | 先用现有 session、来源/context、修订、游标和 issues 验证；只有真实接续缺口才增加状态，翻页不推定已观察 |
| 必要视觉补看 | 复用 uniform/adaptive/scene/dense、精确帧和裁切；保留字幕未提及的画面，不用全局降清晰度换速度 |

本地语言模型只是可能方案，尚无选型与收益对照；现有 Qwen ASR 不等于这类语义模型。对新流程的判断同时看准确性和响应速度，不能以宿主后来补救成功代替组件独立能力。

### 4. Inbox、队列与历史（已实现；后台消费另行接入）

**已确认的用途。** 用户向组件小号转发视频，自动按收件顺序入队；资源/额度有余量时后台阅读，紧张时保留待办。在现有会话查询“读了哪些”、同步最新队列、指定某条先读及继续讨论，不做专门前端。产物沿用附言和会话中的具体任务；弹幕继续作为可选材料。Inbox 与原消息历史归 Scroll，通用队列与任务历史归 reading_tasks，实际材料读取复用 Reader。

**本批授权与边界。** 用户要求“接下来做 inbox 和队列，先不接入读视频部分，重点作队列和历史”，并选择“旧消息保留为历史，启用后的新视频自动入队”。收件暂以会话主动同步为入口，只读已配置主号与小号的一对一会话。没有常驻轮询、后台阅读或新调度，日试用规则不变。

**当前实现。** Inbox 持久保存原消息、序列/时间、卡片或文字链接、同条消息附言、解析状态和修订；每页原子保存消息、队列关联和游标。新消息扫描与旧历史补入分开，失败可继续。队列按优先级/收件顺序，支持去重、不同任务分开、置顶、暂停/恢复、人工完成、取消/归档、搜索与分页历史。已有本账号材料和相关任务主动提示，但不推定已读。状态与单轮恢复继续复用前一批成果。

**真实初始化。** 北京时间 2026-11-04 13:51:00 启用，保存 15 条历史来信，其中 6 条含视频，未自动加入待办；当次待办为空。分段同步、原游标继续及重复同步已验证，CLI/新 MCP 一致。细节与限制见[Inbox/队列参考](../docs/inbox-queue.md)及[验收](../validation/inbox-queue-20261104/report-source.md)。运行状态以实际查询为准，不根据这个快照假定以后没有新消息。

**保留的后台阅读目标（未实施）：**

- **持久状态与恢复：** 已收件、待处理、材料就绪、宿主实际读完及结果可用分开；关联原消息、视频/分 P、附言、Reader job、消费检查点和结果位置。CLI、MCP、后台与会话查询共用状态；中断不丢件，不把已下载或仅已交付算作已读。阶段、最近进展、执行者、等待条件、底层错误链、成果和恢复条件需可回查，保留当前状态与历史事件。问题证据在 E 节 SCROLL-STATE-20261103-01，不在此重复日志。
- **用户响应与资源：** 查询及时返回现有结果、进度、排队/额度/登录/暂停原因；同步或点读说明动作的实际状态。会话指定视频可提高优先级，避免重复领取；不把查询变成重复处理。后台给日常会话保留余量，B 站请求预算、本地处理资源与宿主模型额度分别判断，未知不可当充足。
- **重复和已有材料提示：** 同一私信重复同步不重复建任务；入队/选择时主动提示已有材料及产物，区分重复提交与带新要求的重读，允许复用或补读，不能仅按 BV 全局丢弃。BV1Cxxt6JEqP 已有材料及 v2 攻略，用户确认跳过；本轮只读 BV1gaxb6NEXz、BV1g3t96kEEF，后续接续先复用这些成果。

**后续建议，尚未授权：** 后台宿主消费、完整阅读结果接续、标签/反馈和探索仍需另定范围。后续 F.5 已授权所选六项显式粗读，但不能因存在 pending 项自动调用 Reader、batch-next、round.run 或模型。人工 done 只表示用户标记，不证明宿主读完。

**后续需要确定的机制：** 是否改为自动同步及运行窗口；若另行授权接读，再确定模型余量入口、未知时策略、前后台分配、消费检查点、实际结果和后台恢复。收件范围与旧消息处理已确认，不必重问。现有单轮 recover 仍为显式留档续做，不把后续建议当作实施计划。
