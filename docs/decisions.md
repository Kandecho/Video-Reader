## 2026-10-29 目的核对与及时回答

用户要求先回看最初服务目的、实际服务方式及调用 Agent 是否偏离，再讨论机制的程度。原目的继续成立：“让 agent 可以像看图片、看文字一样看视频”。Reader 为现有 Agent 提供通用、可继续读取和回查的材料；支持先看再聊，也支持带着问题深入，笔记不作为前置步骤。

用户补充：按需读取除了设备和成本，还要考虑响应速度。希望从已快速校对的材料定位，重点查少量疑点后及时回答，保留尚未核查、追问时可继续查看的部分。

据此确认：响应速度属于体验目标。已足以回答与全部材料已核查可以分开；宿主主动处理影响当前答案的疑点，不把所有细节等深度核查作为每次回答的前置。关键疑点暂不能核定时，先回答有依据的部分并说明受影响的判断。无关待查项保留在材料中，不必逐条进入用户回答。

完整性要求保留：材料不截断、不以摘要替代原文，不降低必要清晰度；回答覆盖当下需求，完整总结仍需覆盖相应内容。快速回答不等于把未核查内容标成已核准，按需深入也不能漏掉字幕未提及的画面。

## 2026-10-29 初步校对的职责与验证状态

用户追问当前谁负责校对，以及不调用较强宿主模型时 Reader 是否能独立完成初校。已核对事实：Reader 做获取、ASR、抽帧/OCR、差异提示与局部复听，校对接口保存宿主提交的修改；语义判断目前仍由宿主完成。已有校对稿可复用，首次材料不会自行变成语义校对稿。Qwen ASR 也不是另设的语境校对模型。

本次讨论形成的建议是让 Reader 承担更多基础加工：整理重复展示、对照来源、提供候选修正和有依据的局部重听，宿主集中处理理解及影响当前答案的疑点。用户要求据此更新文档；这项建议尚未变成具体实现方案或已验收能力。

现有错例表明局部能力有效，但不能承诺自动修好多数实质错误并找齐其余疑点。重听读对某句不证明组件会自行发现那句；术语提示曾改善一处并引入另一处错误；OCR 多次一致也不能保证正确。候选机制需要比较正确修正、误改、关键漏报以及首次可用回答的时间。是否增加本地语言模型尚未决定。

本轮授权为文档更新与清理。保留现有功能；不据此安装模型、改变默认引擎、启用云端、启动自主初校或发布。旧 Skill/MCP 的逐段校对要求与新体验之间的差距已列入路线，尚未完成运行行为同步。
