# 早期刷视频 Agent 构想（历史参考）

身份：初期讨论原稿，下文“已确定”“以 BiliLearn 为底座”“不考虑公开”不代表当前决定。现行方向见[决定记录](decisions.md)及[路线](../planning/roadmap-20261021-source.md)；原文保留用于追溯，未转为实施清单。

目标：整理目前确定的本地刷视频 Agent 实现方案｜方式：以 BiliLearn 为底座，整合其他项目中有价值的功能，明确第一版的开发范围

目前可以确定采用 Clone 现有项目 → 本地修改 → 保留有用模块 → 补充少量新功能 的路线。不需要重新开发整个 Agent，也不考虑公开发布。

## 一、项目定位

做一个仅供本地使用的刷视频 Agent，拥有自己的 B 站账号，能够自主浏览推荐、选择和理解视频，积累观看历史，并根据自己的判断及用户反馈逐渐形成兴趣。

它应当具备一定的自主选择能力，但不需要专门模拟人格、情绪、作息或社交生活。

平台方面，第一版先支持 B 站，同时避免把整个程序绑定在 DSH 或 B 站的专有接口上，为以后迁移到其他 Agent 宿主和视频平台留下空间。

## 三、第一版实际需要完成的功能

1\. 独立账号与推荐流

Agent 使用自己的 B 站账号，能够保存登录状态、读取个性化推荐、关注动态及搜索结果。区分平台实际观看历史和 Agent 本地理解历史。

2\. 视频发现与题材查找

保留 BiliLearn 的候选选择逻辑，借鉴 dsh-bili-whale 的关键词搜索、热门、排行、关注来源。Agent 可以根据当前兴趣寻找题材，也可以从推荐流中发现新兴趣。

3\. 视频内容理解

优先使用标题、简介、字幕和 B 站原生缩略图；必要时补充语音识别、FFmpeg 抽帧。借用弹幕热区、刷屏过滤和评论分析来补足视频语境。

4\. 观看历史与日记本

保留每次发现、选择、观看或跳过的视频记录。Agent 可以用自己的语言写下观看感受，形成可回顾的日记。不要求每条视频都写长篇分析。

5\. 简单的偏好学习

Agent 从视频内容、自己的感受以及用户反馈中提取喜欢或不喜欢的原因。维护一份自然语言偏好文件，在下一轮选择视频时读取并调整判断。暂不建立复杂的偏好评分或知识账本。

## 四、本地工程的组织方式

建议保留 BiliLearn 原来的 Python 技术栈，在此基础上调整模块，而不必为了统一技术栈强行重写全部功能。

初步目录可以组织为：

video-agent/

本地 Clone 仓库

platforms/

B 站账号、推荐、搜索、平台适配

video/

字幕、缩略图、弹幕、视频理解

agent/

选片、判断、观看循环

memory/

历史与偏好读写

data/

本地账号数据、观看记录、日记

config/

模型及运行配置

这是目标组织方式，不要求一开始就把 BiliLearn 原有目录全部改成这样。先保留能运行的代码，再逐步隔离不同模块即可。

本地仓库仍然使用 Git 管理修改，保留原项目的来源与许可证文件。账号 Cookie、密钥以及个人观看记录不提交到版本库。

直接 Clone 比 Fork 更符合当前用途：不打算向上游提交，也不需要在 GitHub 建立公开派生仓库。可以保留 `upstream` 远端，以便以后选择性参考上游更新，但不要求持续同步。

## 五、开发顺序与第一版完成标准

建议按照真实依赖关系推进：

1. 跑通 BiliLearn 底座：确认账号登录、获取推荐、LLM 选片、查看视频资料的链路可用。
2. 接入视频理解增强：先实现原生时间轴缩略图，然后补弹幕筛选、热评和其他必要的内容获取手段。
3. 加入本地历史与偏好：记录每次观看和评价，让 Agent 能通过用户反馈逐步改变后续选择。
4. 精简原有项目：逐步移除不使用的学习、社交、复杂画像等功能，保留必要的本地运行入口。
5. 整理平台适配接口：使 B 站专有代码集中管理，为将来更换视频平台和 Agent 宿主做好准备。

第一版的验收可以非常直观：

给 Agent 一个独立 B 站账号，让它自己从推荐流中选择几条视频并形成观看记录。用户随后告诉它其中哪些有趣、哪些无聊，或者提出更具体的意见。下一次运行时，它能够参考自己的观看感受和这些反馈，改变选择倾向，并解释为什么选了新的内容。

只要这个循环稳定跑通，就算完成第一版。暂时不需要评论、私信、直播互动、复杂记忆管理，也不需要独立的桌面 GUI。

后续要扩展能力，可以继续从已有项目中挑选，而不必一开始就将它们全部集成。
