## A 最终要得到什么

让 Agent 像读图片、文字一样读取视频。用户给链接、BV 号或本地文件，之后直接自然语言讨论。Agent 自己完成获取、阅读、核对、保存和必要的返读。

视频是原始媒介，笔记是可选产物。用户用自然语言提问，Agent 自己选择观察方式并取得足够证据。完整性按任务界定，同时减少无效读取；采样、定位和补看服务于这种体验。

当前收窄为“视频/链接 → Reader → 通用、按需披露、可回查的材料”，便于独立接入 CLI、MCP 和宿主薄插件。宿主可进一步生成文字或 HTML 图文笔记；0.10.0rc1 已实现无损交付契约与可移植导出。

Scroll 的账号推荐、偏好与日试用是独立消费方，保留已确认路线；其运行规则见[日试用说明](../daily-trial.md)。它的长期收益不是 Reader 公开的前置条件。

2026-10-24 将仓库公开列为后续优化方向。先验证组合收益、守住职责与证据边界，再准备可独立复现的干净源码交付。它是对外复用的工作，不增加第三套阅读实现，也不要求先完成个性化推荐；计划与去重见 F 节。

自主运行的交付不新开聊天，只使用私信与本地记录。现有按链接阅读和自然语言讨论仍可使用；本开发会话也不属于自主推荐的交付产物。

| 已确定的原则 | 当前含义 |
|---|---|
| 阅读能力可被其他 Agent 复用 | 独立组件，提供 CLI、MCP 和宿主调用流程 |
| 平台适配可各自配置 | B 站处理 BV、分 P、账号与字幕；YouTube 保留独立配置 |
| 默认本地处理 | 本地抽帧、OCR、ASR；Gemini 默认关闭，无自动云端回退 |
| 完整性、准确性与读取消耗 | 先满足任务所需证据与清晰度，再减少无效获取、处理和重复读取；限制通过分批与准确续读处理 |
| 按需披露与完整续读 | 默认校对正文，原文、修改理由及证据可展开；全量材料保留可取得路径 |

早期“以 BiliLearn 为底座”的[构想](../刷视频agent-idea.md)保留为历史参考，当前采用独立 Reader / Scroll，不据此另起底座迁移。

## B 三块职责如何衔接

```flow
平台适配与独立账号 -> 通用视频阅读: 获取视频和字幕
用户主题 -> 基础搜索与热门发现: 已实现
基础搜索与热门发现 -> 通用视频阅读: 宿主选择候选
用户链接或BV号 -> 通用视频阅读
通用视频阅读 -> 宿主Agent: 时间戳画面与语音证据
宿主Agent -> 校对稿及证据缓存: 语境判断和忠实校对
校对稿及证据缓存 -> 自然语言讨论: 默认正文及按需证据
可选参数化唤醒 --> 推荐与选片模块: 已接通，仅首页首条日试用启用
推荐与选片模块 --> 通用视频阅读: 已复用正式组件
推荐与选片模块 --> 本地记录与单向私信: 已接通，按当前授权范围启用
用户反馈 --> 历史与偏好: 已保存真实反馈
历史与偏好 --> 推荐与选片模块: 长期收益待验证，自主探索待实现
```

这些是逻辑职责。当前 B 站账号代码仍位于 Video Reader 内，尚未抽成单独的平台服务。

组件负责获取、抽帧、字幕、ASR、OCR、复听和证据存取。宿主 Agent 负责理解语境、判断冲突及校对。组件没有额外运行一个校对语言模型。

Scroll Agent 已调用同一阅读能力。Reader 会话缓存复用视频材料；Scroll 另行维护兴趣、反馈和运行记录，二者不混为一种状态。

动态画面当前只检查显著数值或公式的局部变化。默认向后观察 10 秒，以 2fps 最多取 32 帧。它仅观察文字保持，不宣称动画语义已结束。缺少通用动作追踪、镜头/事件边界和声画同步语义；非常短的事件可能落在抽样间隔内。

原生声音当前明确返回 raw_sound_understood_by_host=false。ASR 和对齐只回答“可能说了什么、可能何时说”，没有独立的音乐/音效识别、韵律/说话人分段或连续声画联合读取。默认关闭的 Gemini 入口不算这项缺口已补齐。本轮新增的是本地声音测量，没有新增视听模型或云端上传。
