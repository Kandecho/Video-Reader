**先确定要完成的工作，再决定如何处理视频、留下什么、怎样交付。**

视频材料可反复使用；一次读取、取帧、分包或比较属于处理记录。任务针对材料，具有明确目的和完成条件。读完视频、写出摘要或选好留存分类，都不能替代任务本身。

## 原话、任务、材料与成果

| 对象 | 保存什么 | 不能代替什么 |
|---|---|---|
| 用户原话 | 精确附言、来源消息或会话确认依据 | 不把归纳后的要求冒充原话 |
| 实际任务 | 具体问题、判断目标、待验证操作，以及完成条件 | 不默认改成“给视频写笔记” |
| 材料 | 正片、字幕、原声、画面、简介、评论、弹幕和必要外部来源 | 材料已取得、已看过，不代表工作已完成 |
| 处理记录 | 获取、读取、取帧、分包、比较与校对等实际过程及覆盖 | 不因发生一次处理就新增任务，也不据次数推断任务完成 |
| 实际成果 | 回答、判断、试用结果、字幕、案例或学习资料 | 目录标注、计划格式和处理状态不能当成成果 |

同一视频可以服务多个任务，一个任务也可以使用多种材料；已有笔记也能成为另一项任务的材料。任务与来源各有身份，视频标题中的问句或号召不自动成为用户要求。任务边界按目的与完成条件确定，不按操作次数、产物数量或提出时间确定。

先保留原话，再提取具体工作。已有明确关联或用户确认的附言可用于任务；独立私信不只凭相邻位置自动配对。评论性附言可以只作背景，不自动扩大成新任务。

## 单次任务的核心字段

| 字段 | 职责 | 值域与维护 |
|---|---|---|
| 任务状态 `state` | 这项任务推进到哪里 | 固定为pending、paused、done、cancelled、archived，不得为空 |
| 任务类型 `task_type` | 要完成哪类工作 | 可选短文本；同一目的先复用已有名称，确有不同目的再新增 |
| 任务描述 `task_description` | 具体对象、要求和完成标准 | 可选自由文本；保留原话另作依据，不用类型名称代替实际工作 |
| 完成方式 `completion_method` | 必要时说明任务怎样结束 | 可选短文本，只在done时填写；例如用户确认以“终止”完成 |

目录以状态、类型为主筛选，描述和处置可用关键词查找。类型不是固定类别枚举，也不随视频主题或保存目录增殖。先查看同任务库的 `queue-list.task_types` 历史建议，相同含义沿用原叫法；程序不模糊猜测或自动合并。未填写类型不等于任务待处理。

这些字段由任务库维护。`task`保留原正式要求及兼容入口，当前具体工作使用canonical `task_description`；旧目录元数据中的类型式描述或task_goal不重新冒充核心字段。新建时未单独传描述，旧非空task可初始化描述；之后明确清空的描述保持空值。执行时需要具体要求，空描述可通过显式request提供，不能从标题自动补造。

新增可选核心字段task_type、task_description和completion_method未填写或清空时统一为JSON `null`。空字符串和纯空白归一为null。可选目录呈现文本、来源cover_path和处置reason／notes也可清空，具体字段见[目录契约](master-catalog.md#空值与更新)。旧task／title及result答复仍遵循原有字符串契约。

更新时**不传字段表示保留，显式null清空nullable字段**。purposes、tags和处置artifacts用 `[]` 清空。必填状态、处置description不能用null替代。界面“未注明”“未填写”是占位文案，不入库；不存“无”“待确认”等文本占位，也不从旧标签恢复被清空的值。

离开done时完成方式清空。未单独记录完成方式时保持null，不自动填“正常完成”。

## 任务处置与留存去向

任务处置说明这项工作实际怎样落定，包括回答了问题、收藏、保存笔记、另存已有成果或决定不另存。它可以属于同一任务，无须因发生在整理之后就成为新任务。比如“学习一下”的任务是整理笔记，整理完成后另存KIBRARY或“无新增认识，不另存入知识库”都是该成果的留存处置。

实际答复或成果已经说明的处置，直接从该成果回查，不为显示“已回答”重复登记动作。另存位置、留存决定或待执行步骤需要独立说明时，再追加相应记录。

分别保留两个理由：为什么处理材料，以及为什么把成果另存或不另存。整理完成说明约定的理解与成果已形成；是否进入知识库，还要依据新增认识、复用价值与已有内容判断。不另存可以是完整、有依据的处置，原笔记仍可回查，以后有新问题时可以再次处理。

实际副本保存并核对后才登记已存入及文件位置。已决定另存但尚未执行的处置保持pending／paused，不被父任务done掩盖，也不参加父任务状态与类型筛选。明确“不另存”的决定可以done且无新文件。未要求的分流或后续步骤不自动变成待办；需要独立加工、整合、补证或其他明确目的时，再判断是否另立任务。

用户确认以终止结束不可获取任务时，可以是done、完成方式“终止”。这只说明处置完成，未读取视频、未核查主张仍须明确保留。撤销或取消的需求不一概转成done。

## 三档留存分类单独判断

“简述索引、轻量记录、深度提取”描述**处理后留下什么、怎样组织**。它们不决定实际任务、用途、读取深度或最终交付。

| 留存分类 | 主要判断 |
|---|---|
| 简述索引 | 有充分替代资料时留下简述、来源与回查入口 |
| 轻量记录 | 留下独有演示、经验、讨论增量或紧凑判断 |
| 深度提取 | 组织重要概念、过程、证据及可复用步骤 |

先对照真实材料再决定分类，不能因存在GitHub就推定视频没有增量。读取可以很细，成果仍然简短；深入读取也不必生成长篇学习笔记。

## 按任务选择交付

| 实际任务 | 首要交付 | 验收重点 |
|---|---|---|
| 回答问题 | 问题、直接回答、理由及局限 | 是否回答了用户真正问的事 |
| 核查观点 | 判断、证据、反证及未决部分 | 片内论证分析与外部事实核验分开 |
| 判断工具好用不 | 实际试用结果、适用场景及限制 | 演示介绍、代码查看与亲自试用分开 |
| 翻译 | 目标范围内的译文或字幕 | 原文、时间轴、修订及疑点可回查 |
| 案例收录 | 具体案例、想法、来源与上下文 | 按实际收录目标和本地技能完成 |
| 学习或操作参考 | 可理解、可复用的概念或操作材料 | 必要画面、步骤、条件和边界保全 |

例如VCP-note要交付论证区别和作者意图的直接回答；GPUI要回答是什么、与Electron相比怎样服务AI开发；Nord配色的颜色与操作效果需要实际保留。三者都可以属于轻量记录，成果形态仍不同。

只需回答问题时，直接答复本身就是成果，不强制另写笔记文件。摘要不能自动冒充针对原问题的回答。保存成品默认HTML；只有文字占绝大部分、重要信息可完整由文字承载时才选Markdown。明确任务另有要求时按任务交付。

## 完成与登记

先按明确要求检查成果：问题是否答到、必要核查是否做过。再检查讨论是否读过、试用是否真实进行、所需HTML是否生成并查看。HTML需要保留的视觉信息应进入实际页面，不能只更改扩展名或把目标写成HTML。

用户仍要求完成原目标时，实际要求未满足就保存有用草稿。列明具体缺口与继续入口，任务保持未完成。用户明确同意终止时，可以记录done与完成方式“终止”。这只表示约定的关闭处置完成，不声称未做的交付已经实现。

旧done与旧成果保留历史。发现完成标记与实际工作不符时纠正当前状态，不能用通用整理完成冒充目标完成。

成果登记保存实际任务、直接结论、覆盖范围、来源依据、产物及仍未解决的问题，随后更新本地总目录。分类、读取投入、格式各自记录。实际交付与目标格式分开；批次只是总目录的筛选投影。

完整观察、语义校对、任务满足和全片核验分别判断。材料已足以回答时及时交付，不把全片逐字校对当作每次任务的前置条件。
