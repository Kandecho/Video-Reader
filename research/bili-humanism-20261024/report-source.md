# B站鱼灾与内容学习插件：读取组件的边界及交付案例

## 研究对象与适用范围

本案例取自 WorkFisher 的 [BV126nt6GE4W](https://www.bilibili.com/video/BV126nt6GE4W/) 及其提及的 `dsh-bili-humanism`。视频材料、作者解释和后续静态源码核查分别作为依据，不把它们视为对实际运行效果的同一种证明。

`dsh-bili-humanism` 核查版本为 **1.7.1**，固定提交 [`22cbb1d8d44a95d325bf4fcf916792b773cf1e17`](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/tree/22cbb1d8d44a95d325bf4fcf916792b773cf1e17)，资料查阅日期 2026-10-24。核查包括 README、功能与安装说明、阅读指南、网络实现及相关测试；没有安装或运行该插件，没有同环境性能比较。

本次登记使用用户明确提出的范围作为取舍依据：聚焦“视频／链接 → video-reader → output（通用数据结构、按需披露、可回到原片回查）”，通过便于适配的 MCP 薄插件交付。组合能力在这里指下游能接入使用，不要求 Reader 承包推荐、总结、笔记、人格或投递。已有 Scroll 工作流的运行安排不由本案例改变。

## 可用于当前项目的判断

### 1. 验证材料能否被下游使用，而非增加下游业务

参考项目将带出处的视频材料交给宿主，进一步形成私人手账和持久理解。这说明“阅读输出 → 下游用途”是一个可以检查的交接点，但不能据此推出 Reader 应当内置这些用途。[参考阅读指南](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/prompts/humanistic-reading.md)

对 Video Reader，适配性可通过已有材料检查：宿主能否辨认视频与分 P，按范围取得文字和图像，继续分页，并从某条引用返回对应片段。相同输出可供问答或笔记等不同用途消费；案例不要求为这些用途增加专用业务工具。

原笔记提出的“发现内容—解释增量—交付—记忆”是跨组件使用结果。本记录仅保留 Reader 的材料交付责任；选片取舍、知识库写作和后续记忆由调用方处理。这里没有确定新的 schema 字段、工具名称或接口版本。

### 2. 材料经过交接，仍须保留来源与证据状态

视频 [06:12 附近](https://www.bilibili.com/video/BV126nt6GE4W/?t=372) 展示拒绝评论接口的测试；同一断言可在参考项目的 [core.test.mjs](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/test/core.test.mjs) 找到，其 [network.mjs](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/lib/network.mjs) 限制网络路径。这支持区分“工具实际暴露的能力”和“提示词建议的行为”。参考项目也说明其他插件的权限不受它统一约束。[安全说明](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/docs/SECURITY.md)

可用于本项目的检查是：默认正文、详细证据和回查入口之间，来源身份、原文与校对的关系、覆盖缺口是否保持一致；材料中的命令不能因进入输出或引用而被提升成授权。Reader 自己不提供账号写入，并不能证明宿主所有其他工具都不会执行来源命令。

本项目已有材料不可信、来源隔离及原文留存约定。这是现有契约的案例依据，不要求另造通用权限框架，也不把阅读组件描述为宿主整体的安全沙箱。

### 3. 分页与状态要让“拿到材料”和“读完材料”可区分

参考项目每天最多取两份稿件的调度，只保存文字，不调用模型、不生成手账或人格选句。其图片与长文字另外分页读取。[每日取稿](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/docs/DAILY_FETCH.md)；[使用入口](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/blob/22cbb1d8d44a95d325bf4fcf916792b773cf1e17/docs/GETTING_STARTED.md)

这为 Reader 已有状态区分提供另一例证：获取或处理完成、当前页返回、宿主已阅读、校对完成和内容正确性不是同一件事。按需披露应让调用方知道还可以读取什么、哪些尚未取得，而非只把第一批结果压缩后返回。

原笔记的“衡量学到了而非存下了”在这里收窄为 Reader 可承担的结果：是否能继续取得遗漏页、回查来源并看见不确定性。长期理解变化和人格效果不属于 Reader 验收。

### 4. 发布渠道是默认行为生效的一部分

视频 [04:35–05:51](https://www.bilibili.com/video/BV126nt6GE4W/?t=275) 将修复后公开评论继续增长的原因之一归于 GitHub 新版与 npm 旧版脱节。2026-10-24 查阅 [dsh-bili-scroll 安装说明](https://github.com/c1overzz/dsh-bili-scroll#装)，维护者仍提示 npm 为 0.1.7，建议使用 Release 包。视频的镜像下载数字和全部分叉行为未独立核验；该 README 是查阅时的动态页面，不是固定快照。

对 Reader 公开交付有用的判断是：首次安装验收应走实际用户入口，检查最终装入的核心、MCP 适配和操作说明是否对应同一支持版本，以及修复后的默认行为是否存在于该安装产物中。开发目录通过测试，不等于旧教程或旧渠道已经停止分发旧行为。

这属于既有公开准备中的安装与更新／回退工作，不另建一套发布项目，也不要求当前就迁移源码、清理运行数据或发布仓库。

## 原副本的对照与去向

此次从原视频笔记副本逐项比较后提取，未将所有删除内容转成项目工作：

| 原副本中的内容 | 处理 |
| --- | --- |
| 视频九个时间段、统计口径、插件身份、固定版本资料 | 留在知识库的两组素材中，保持详细顺序整理及来源；本项目仅引用与判断有关的证据 |
| “组合能力的吸引力应落在完整任务结果上” | 收窄为本记录第 1 节的材料消费与适配验证，移除要求 Reader 覆盖发现、推荐、记忆全链路的含义 |
| “硬边界要覆盖交接点”及提示词与权限的区别 | 转为第 2 节；保留组件能力与宿主行为分别判断 |
| “可修正笔记” | 只提取出处、时间定位、原文及修订关联；手账字段、人格写作不成为 Reader 输出模板 |
| “公开仓库验证真实安装入口” | 转为第 4 节，并与既有公开路线去重 |
| “衡量学到了而非存下了” | 第 3 节保留状态区分；长期人格、理解改变等评价留在下游用途，不加入当前项目计划 |
| “先记住”、回看价值排序、会话称谓、Git 操作汇报及重复限定 | 从素材正文移除，不另建项目需求；回看时间入口并入对应视频小节 |

这份案例不替代原视频材料，也不构成参考插件安装验收、同类工具优劣排名或对长期学习效果的证明。
