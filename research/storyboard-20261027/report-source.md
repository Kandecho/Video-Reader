归档说明：这是计划合并前的调查记录，保留当时结论和范围。2026-10-27 用户已要求将采用项并入现有路线；当前优先级、实施状态和保全要求以[路线 F 节](../../planning/roadmap-20261021-source.md#f-后续按什么顺序推进)为准。

**它是值得参考的同方向实践：让宿主 Agent 直接观察视频材料，并自主决定下一步看哪里。** 它把这条路线收敛成几个易用的观察动作，在资源预算和交互表达上很有针对性。整体状态是可运行的早期组件，全文保真与部分边界行为仍需完善。

这里评估的是“让 Agent 读视频”的整体想法。本轮分镜更新只是局部背景，不作为评价它的主要尺度。

## A 它和我们的整体想法哪里相近

它提供图片、台词和时间索引，让当前宿主自己观察、引用并继续提问。这与我们的“视频是原始材料，宿主负责理解，笔记是可选产物”方向相近。当前注册三个动作：先探测容器和阅读计划，再取总览，遇到疑点后缩小时间窗。[工具说明](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/tool-spec.js)、[实际注册](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/index.js)

```flow
视频文件 -> video_probe: 时长、轨道、阅读计划
video_probe -> video_storyboard: 取一个窗口的图与台词索引
video_storyboard -> 宿主观察: 读图片、引用格号和时间
宿主观察 -> video_zoom: 放大疑点所在时间窗
video_zoom -> 宿主观察: 返回更大的画面
```

这套动作的价值在于：Agent 不必先学一长串参数，就能走通“看一遍、找到疑点、回到原片”的过程。所谓 text-only agent 在这里仍需要读图片的能力；它解决的是视频输入和观察组织，不会让纯文字模型获得视觉能力。

## B 设计里做得好的地方

| 方面 | 实际设计 | 对整体目标的帮助 |
|---|---|---|
| 可寻址材料 | 图上编号；文字列出格号、行列和时间区间 | 宿主能引用同一位置并提出局部追问 |
| 观察密度 | 用镜头变化及局部切换密度分配时间格位 | 有限画面预算能更多照顾变化密集的区域 |
| 代表帧 | 每段取三个候选，用清晰度指标挑一个 | 减少把模糊转场当作唯一材料的机会 |
| 由粗到细 | 总览之后用 zoom 减少格数、增大每格 | 兼顾概览成本和屏幕文字的可读性 |
| 轻量实现 | Node 与 FFmpeg；CLI 和宿主共用管线 | 部署负担较小，也便于独立检查产物 |
| 视听对齐 | 图下附响度、静音区间和切点条带 | 提供可测量的声音线索，帮助定位返看位置 |

镜头密度曲线、清晰度挑帧和响度条均有实际实现，不只是 README 的设想。[密度分配](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/density.js)、[取帧与拼图](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/sheet.js)、[音频测量](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/audio.js)

这些信号仍是观察辅助。镜头变化不等于语义重要，最锐的帧不一定最关键，响度也不能说明音乐含义或人物情绪。作者在边界说明中承认了后一项，这个取舍是清楚的。

## D 从“能观察”到“可靠读完”的缺口

**最重要的缺口是材料完整性。** 默认文字索引每格最多 180 字。

我构造了一格 350 字的输入，首次得到 180 字；用 cellRange 再取同一格，仍是相同 180 字。整格截短没有对应的后半段续读提示。缩小时间窗或调用更底层函数可能绕开，但默认工具没有一个明确的全文展开入口。[文字输出实现](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/pipeline.js#L369)

它的整页预算会在格子边界停止，并给出下一格，说明作者重视宿主上下文溢出问题。不过“所有格子都翻完”和“所有台词都读到”仍是两个状态。这个区别会影响整片讨论和细致校对。

**原文与处理结果的关系也还比较粗。** ASR 后会按启发式过滤疑似音乐幻觉，并按用户词典替换术语。返回值报告过滤及替换次数，但没有逐项原文、修改依据和审阅版本。底层 ASR 缓存通常仍保存识别结果，尚未形成可供宿主直接使用的原文与校对证据层。[ASR 处理](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/asr.js)

例如我给过滤器一条跨 12 秒的“等一下”，它因字数密度低被归为 music-like。实际输入里这可能是幻觉，也可能是带停顿的真实话语；只靠这一规则不能判定。对要求完整阅读的任务，更稳妥的交付是保留原文并标疑。

另外复现了三项工程问题，均存在于本次固定提交：

| 问题 | 复现结果 | 影响 |
|---|---|---|
| HSV 色相差没有按色环计算 | 几乎相同的两种红色得分 84.89；近灰色得分 56.67 | 可制造假切点，影响观察位置的分配 |
| 极短窗口 | 0.05 秒窗口得到空分段；拟合时抛 TypeError | 局部返看在边界处可能失败 |
| index+time 参数 | 与 index 输出字节完全相同 | 实际未烧入承诺的时间码，仍依赖文字索引 |

上游 [Issue #1](https://github.com/SAOS-3624/dsh-video-storyboard/issues/1) 和 [PR #2](https://github.com/SAOS-3624/dsh-video-storyboard/pull/2) 已讨论这些问题；检查时 PR 尚未合并。本次以固定主线提交为准，没有把 PR 中的修复算作已发布行为。168 项测试全通过，也说明这些边界尚未被现有测试覆盖。

## E 与我们整体路线的关系

| 维度 | dsh-video-storyboard 当前实现 | 我们现有 Reader 主线 |
|---|---|---|
| 核心方向 | 把视频变为宿主可以直接观察和追问的材料 | 相近；宿主负责理解与讨论 |
| 观察入口 | probe → storyboard → zoom，动作集中 | open/read、语音、局部返读等材料入口较多 |
| 画面策略 | 重点优化少量格子的挑选与像素分配 | 保留抽帧、原时间、局部精读与证据复用 |
| 语音与校对 | 字幕或兼容 ASR 服务，台词贴到格子；启发式过滤与词典 | 全文分页、来源隔离、原文与修订、证据和复听 |
| 状态与复用 | 文件、窗口、格子、扫描和 ASR 缓存 | 持久会话、阅读记录与校对版本 |
| 声音线索 | 响度与静音的可视化测量 | 主要是语音材料；同样不能据此声称原生声音理解 |

它给我们的启发主要在**如何让 Agent 更容易决定“接下来该看哪里”**。相比继续堆参数，这种观察动作的组织值得吸收。我们的原文、修订和来源保留则服务于另一项重要要求：结果有疑问时能查清依据。两方面可以结合。

对你“正确、完整优先”的偏好，应先保证材料能完整取得，再根据问题选择低成本总览或细读。它的低分辨率拼图适合发现线索，文字、公式和短暂动作仍可能需要返看。

## F 怎么看它的价值与成熟度

**我的判断：整体想法清楚，观察和追问流程有用，核心实现已经跑得起来，值得持续参考。** 它关注当前 Agent 如何使用原始材料，有助于保留宿主的判断空间。

当前公开版本是 0.2.0，仓库在 2026-10-27 北京时间创建，仍处于很早的迭代阶段；已带单元、媒体端到端和宿主契约测试。短窗口、切点正确性和全文展开等问题还会影响日常可靠性。[发布记录](https://github.com/SAOS-3624/dsh-video-storyboard/releases/tag/v0.2.0)、[CI 配置](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/.github/workflows/test.yml)

“一张图 384 tokens”是它针对特定 DSH / DeepSeek 图像预算采用的估算口径。源码直接定义该常量，不能据此推算其他宿主或模型的账单；probe 和 textOnly 省掉图片开销，文字输出及处理仍有成本。[预算实现](https://github.com/SAOS-3624/dsh-video-storyboard/blob/c135bb34ea4b59414cd7416517e003428488ed3f/src/plan.js#L1)

本次建议是借鉴其观察动作、按材料分配预算、图文可寻址的做法。完整语音、证据和修订机制继续保留。没有安装或合并对方代码，也没有据此新增实施任务。
