## A 日常试用只简化选片，不阉割其他能力

```flow LR
Windows 每日 20:00 -> Scroll Agent: 执行一轮
Scroll Agent -> 小号首页接口: 固定首个有效普通视频
小号首页接口 -> Video Reader: 读取画面和语音材料
Video Reader -> Scroll 判断: 宿主结合记忆评估
Scroll 判断 -> 主号私信: 每日一条试用
Scroll 判断 -> 本地记录: 内容范围、判断与投递状态
```

只取接口返回的第一条普通视频，跳过广告和非视频项。
不因偏好、已看历史或模型评分换成第二条。
即使判断“不推荐”，仍作为首条试用发送。
正常读取、可选深读、记忆和真实反馈都保留。

同一天只固定和投递一条，失败不自动换片或连发。
跨天如果平台首条仍相同，允许再次出现。
账号源是组件小号；投递目标是你的主号。
接口批次不保证与手机或浏览器某次刷新完全相同。

## B 你的边界判断正确，已落实到代码和 MCP

**Video Reader 是通用能力；Scroll Agent 是个人工作流。**
“帮我挑两条视频”是普通请求，不是品牌口令。
普通主题选片可以直接用 Reader，不依赖 Scroll。

| 组件 | 负责 | 不负责 |
|---|---|---|
| Video Reader | 搜索、热门、预览、读取、转写、校对、复听和组件登录 | 个人记忆、私信和调度 |
| Scroll Agent | 账号流策略、偏好/反馈、日记录、投递和触发 | 第二套下载、转写或模型实现 |

Reader MCP 为 9 个通用工具。
Scroll MCP 只提供 `scroll_round` 和 `scroll_memory`。
Reader 预览不再初始化 Agent 或 SQLite。
其 transport 默认只读；私信端点只由 Scroll 显式允许。
提前调用日试用，也不会在 20:00 前冻结当天候选。

两个 MCP 和 Skill 分开，但仍组合为一个薄安装包。
同一环境、配置、模型、登录与缓存共用，没有复制核心。
源码是 Scroll 单向使用 Reader，不把自己绕成远程 MCP 调用。
旧 Reader MCP 中的 `video_agent` / `video_memory` 已移出。
旧 CLI 仅保留惰性兼容桥，当前入口是 `scroll.ps1`。
