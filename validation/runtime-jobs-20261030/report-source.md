## A 已完成的修复

**CLI 和 MCP 已能查询、接续同一个 Reader 任务。** open/read/transcript 默认等待 1 秒，未完成就返回 job_id；任务在独立进程中继续。重复的同参数活跃请求接续原任务，已完成请求则重新读取当前材料，避免遮蔽后来的校对修订。

状态分开报告阶段、心跳、真实进展、等待的会话或账号锁、已就绪材料计数与终态。状态查询不取得视频材料锁。未观察到启动时保留 unknown，已运行后失去所有权则报告 interrupted，均不自动重启或恢复平台暂停。

独立实测发现的旧阶段 message/progress 残留已修复。独立审查还复现了并发查询把另一个观察者误认成 worker 的问题；现以专用查询短锁区分观察者与任务所有权，原审查代理针对性复核通过。

同步 Python Reader API、原文/校对、采样策略、默认 OCR 深度和材料分页继续保留。materials 表示缓存可用性，完成结果只交付普通第一页，不能当成宿主已读完。

## C 子代理一：处理消耗

对象是 BV1Fxxv6YEhC 的原媒体与原字幕，长 411.736 秒。使用独立本地缓存，不复用旧帧、OCR 或校对；没有重新联网下载。新 stdio MCP 初始化 0.952 秒另计。启动早期有短暂本地夹具测试重叠，因此这是实际案例观测，不是严格隔离性能基准。

| 场景 | 任务处理墙钟 | 材料交付调用合计 | 物理交付页 | 帧 | 独立字幕段 |
|---|---:|---:|---:|---:|---:|
| 默认冷处理 | 259.694 秒 | 0.842 秒 | 46 | 11 | 60 / 195 |
| 同参数暖读取 | 0.457 秒 | 0.814 秒 | 46 | 11 | 60 / 195 |
| 0–10 秒单帧、关闭本次两类 OCR | 0.659 秒 | 0.004 秒 | 1 | 1 | 7 |

冷处理抽帧为 4.222 秒，画面时间稳定性 OCR 为 119.032 秒，首批 60 段字幕画面对照为 135.997 秒。两个 OCR 阶段占墙钟约 98.2%。这些是阶段墙钟，不是 CPU 采样。

暖读取有帧与 OCR 缓存复用证据；独立 worker 启动本次约 0.23–0.33 秒，也有可观测成本。不能把冷/暖差异说成算法提速。

主实测阶段 130 次 SDK 状态查询的中位数为 3.44 毫秒，最大 8.07 毫秒。心跳持续更新，真实进展最长 35.8 秒没变化，任务仍在计算。随后修补了状态文案与并发观察者问题，并做针对性验证，未重新跑性能矩阵。

冷、暖各交付约 975 KB MCP 文本、953 KB 解码图像。跟完视觉链得到 11 张画面，但独立字幕仍仅 60/195 段；剩余语音需另跟 speech.next_cursor。处理代理没有把这一步宣称为全片已消费。

## D 子代理二：宿主消费

第二个代理不读源字幕、manifest、父代理总结或另一个代理报告，通过新 stdio MCP 独立读取既有会话。首次默认 video_read 在 1.016 秒返回 running/extracting_frames；客户端重启后沿同一 job_id 成功取得结果，没有重复启动。

本次未沿用原 SeeSide task，因此未命中那份帧记录。任务另行抽帧与 OCR，共 51.613 秒；其中画面 OCR 为 46.433 秒，字幕核验为 0.089 秒。它复用了原会话已有的 revision 1 校对和部分材料，不能与独立冷处理直接比较。

| 实际消费路径 | 调用或交付 |
|---|---|
| 总调用 | 50 次：1 read、1 job result、48 continue |
| 帧材料 | 32 页 + 14 页，共 11 张原生图 |
| 第一次可见语音 | 第 28 次调用 |
| 第一次可见图片 | 第 33 次调用有 8 张；第 47 次再有 3 张 |
| 剩余语音 | 独立 speech 游标另取 3 页 |
| 总结果 JSON | 2,424,643 字节；文本 1,013,096 字节 |
| 语音重复 | 255 个实例，去重后 195 段；重复 60 段 |

**代理最终读完了 195 段字幕，并实际查看全部 11 张返回画面。** 所选语音范围覆盖 0–411.736236 秒；本次使用已有校对阅读层，没有更改 review。这验证材料能够完整消费，不是独立初校准确性或连续视听验收。

两组材料的 visual 分支共展开 9,713 个字段，主要是 OCR、置信度、坐标和时间观察。正文及图片排在这些字段后面。视觉 snapshot 的最后一页还有下一逻辑页；视觉链结束之后，语音链仍未结束。这解释了工具无报错，宿主却很容易提前停止或花很多精力整理的原因。

本次 50 个视频工具响应均无工具错误或服务端静默截断。外层终端曾截断一次检查输出；消费代理通过已经取得的原始工具响应恢复阅读层。它也修正了自身把图片标签 text block 当成 JSON 拼接的解析错误。这些不能归为 Reader 返回了无效 JSON。

内容讨论保存在独立 content-discussion.md；产品技术统计与问题只保留在本记录。

## E 仍需处理的问题

运行任务状态已修复；**默认前置核验成本和材料交付顺序仍未优化。** 首包优先提供可读字幕及画面、减少默认前置重核验、分开物理帧缓存与 task 意图、让语音和画面续读更容易理解，是后续依据。

旧的已连接 MCP 进程不会因源码变化自动热更新；本次独立调用均使用新服务，当前会话也已看到并实际调用新工具。不删除凭据或锁，不为重试切换账号或云端。
