## A 现在怎样交给调用方

默认先返回校对正文、时间戳和必要疑点标记。调用方按区间获取原文、修改依据和词级证据。仍有疑问，再回到画面或复听音频。

```flow
完整语音与相关画面 -> 宿主校对: 首次阅读
宿主校对 -> 校对正文: 保存并复用
校对正文 -> 自然语言讨论: 默认精简返回
校对正文 -> 原文与修改依据: 按区间展开
原文与修改依据 -> 原始画面或复听: 疑点仍未解决
```

首次校对仍需完整语境和相关视频证据。组件没有额外内置一个语言模型。宿主 Agent 执行校对，组件保存结果并分层返回。未校对的稿件明确标为 pending，不冒称校对完成。

## B 接口分别返回什么

| 入口 | 返回内容 | 何时使用 |
|---|---|---|
| transcript，默认 reading | 正文、时间、段落 ID、校对状态、疑点标记 | 日常阅读和追问 |
| transcript，view=evidence | 原文、校对字词、修改理由、帧和复听引用、原始词时间及概率 | 按区间核查 |
| transcript，view=raw | 原文字面及证据 | 比较原始记录 |
| video_review | 分页准备、带证据提交、校对覆盖状态 | 宿主完成忠实校对 |
| video_relisten | 新解码候选、原基线对照、独立记录和超时状态 | 需要新语音证据 |

原始字幕和 ASR 不覆盖。校对保持原段落与时间。全部 words 对齐原始文字，不能把它们当成校对字词的新对齐结果。字幕与独立 ASR 分别校对。

## D 复听做了什么，解决了什么

普通区间重读会复用缓存。新入口每次启动本地隔离进程，真正重新解码。结果单独保存，不替换基线。默认运行限额 60 秒，超时会终止进程树。

短窗试验先遇到漏句、重复及超时。裁切音频与完整音频的对应片段几乎完全一致，排除了本例的错误裁切。进一步观察到默认标题提示反复混入转写。

最终默认不向短窗注入标题。保留分段时间，关闭词级对齐、短片 VAD 和多温度重试。显式 context/terms 仍可提供，但作为可偏置的提示保存。

| 真实区间 | 最终无标题提示结果 | 解码时间 |
|---|---|---:|
| MBTI 233–246 秒 | 完整返回相关四句；仍把移情写为疫情，并出现主体的同音错字 | 18.016 秒 |
| VTuber 16–29 秒 | 返回相关内容，正确读到项目意识 | 14.797 秒 |
| 正式安装的 CLI，VTuber 同一区间 | 从组件外目录独立运行，正确读到项目意识 | 15.016 秒 |

复听成功仅表示解码完成。结果始终标为未核实候选。明显变短和重复会额外提示。移情等同音词仍需整片语境与画面校对，不能自动采纳机器候选。
