## A 比较后选择了什么

本轮选择优化现有返读能力，已实际完成并安装为 0.6.1。判断基于项目现有证据，是当前阶段的工程取舍。

| 路线 | 主要收益 | 现有依据与成本 | 当前选择 |
|---|---|---|---|
| 阅读优化：来源一致与 OCR 调度 | 每次返读都受益，避免切回另一份字幕和不需要的等待 | 已有真实来源限制与耗时问题；不需要新模型或用户反馈 | 本轮完成 |
| 阅读优化：正式接入 Qwen | 有望降低首次转写耗时和部分专业词错误 | 已有 GPU 实验，但仍缺独立参考、边界处理与时间对齐 | 继续作为后续候选 |
| 其他功能：偏好、日记与持续选片 | 更接近日常刷视频 Agent，可让发现结果逐步个性化 | 基础检索已能供片；尚无真实偏好反馈，需新增状态和反馈循环 | 本轮未扩展 |
| 其他功能：YouTube 与更多语言 | 扩大可用视频范围 | 当前主要验证 B 站；仍需独立的网络、字幕和下载验收 | 按实际使用需要推进 |

偏好和跨平台功能有价值。当前更明确的回报来自修复每次阅读都会碰到的问题，也为后续选片循环减少返工。没有用虚构的准确率、工期或 ROI 分数给路线排序。

## B 找到并修复的具体问题

原来的 `transcript` 可以指定 ASR，但 `read` 不接受相同的 source/context/view。视频同时有字幕和独立 ASR 时，返读画面会按 auto 优先字幕，无法保持刚刚选定的 ASR 校对稿。

现在 `read` 和 MCP `video_read` 也接受 source、context、view、verify。source=asr 保持相应校对来源；context 选择同一解码配置，view 可取正文、原文或证据。auto 的字幕优先规则仍保留，read 本身不会启动转写。

第二个问题是 OCR 调度。旧版请求一个精确时间戳的画面，仍可能新算随附前 60 段语音的屏幕核对。这些段落甚至与所取画面不在同一位置。宿主已校对的正文，也仍会为了展示而补算此前缺少的语音 OCR。

| 请求 | 0.6.1 的语音 OCR 行为 |
|---|---|
| 未校对的普通机器语音页 | 自动计算缺少的核对，已缓存的继续复用 |
| 已校对的 reading/raw 正文 | 只复用已有核对，不新算 |
| 精确 timestamps 取帧 | 默认只复用已有语音核对 |
| verify=true 或机器语音 view=evidence | 按当前页补算缺少的核对 |
| verify=false | 不调用语音 OCR |

返回 screen_verification，报告 policy 以及 computed/cached/skipped 段数。跳过不是通过，不会把 pending 改成 reviewed；已有屏幕冲突和未解决疑点继续保留。

temporal 单独控制数值/公式画面观察。timestamps 只选择画面，随附语音仍由 start/end 和分页决定；局部语音问题要显式限制区间。人工 CC 默认仍不核对，verify=true 可显式要求。

## C 真实返读的收益

使用上一轮陌生视频会话的隔离副本，比较 0.6.0 旧 Reader 与 0.6.1。请求 270.8 秒的一帧，随附前 60 段语音。

| 指标 | 旧逻辑 | 新逻辑 |
|---|---:|---:|
| 这次 API 调用耗时 | 51.490706 秒 | 0.013425 秒 |
| 额外语音核对取帧调用 | 86 次 | 0 次 |
| 返回语音段落 | 60 段 | 60 段 |
| 默认正文文字 | 相同 | 相同 |

条件是已有所取画面的帧缓存，但没有语音核对缓存。计时为同一运行进程中的一次 API 调用，旧逻辑包含 OCR 初始化。没有计入进程启动、下载或转写，不能说整片读视频加速了相同比例。

另外验证：未校对会话的普通 transcript 仍新算核对；显式取 39–42 秒 evidence 时，实际计算 3 段、取 4 帧，约 2.22 秒。完整正式语音记录保持不变。

计时完成后，基准脚本曾把本区间第一句误当作修订句，导致后续断言失败。已修正为核对区间内实际修订句，保留完成的计时和原始返回，并续跑剩余验证；没有从失败的调用估算耗时。

## D 如何验证了来源和安全边界

77 项正式安装回归测试通过，其中新增 9 项返读专项测试。真实 MCP 协议验证了新增参数及 raw、captions、asr 的行为。

专项覆盖部分审阅只检查 pending 段、审阅后不新算、显式 evidence 补算、原文键的缓存复用，以及已有冲突继续可见。更换原始转写后，旧审阅状态不能让新内容跳过核对；换 context 也不能复用另一配置的校对稿。

真实 VTuber 会话同时有字幕和独立 ASR。指定 source=asr 后，read 与 transcript 返回相同的段落 ID、校对正文及完成状态。read 不会为了缺少 ASR 而悄悄切回字幕或启动新解码。

修改前快照、原始返回、克隆会话和汇总保存在 `validation/reading-0.6.1/`。基准脚本每次新运行创建独立目录，避免旧 OCR 缓存污染测量。

## E 现在得到什么、还有什么没解决

现在可以更低成本地返回已校对视频，也能在看细节画面时保持指定的语音来源。需要原文和核对依据时，仍可按区间展开。README、宿主流程、知识路由、路线总览与 handoff 已同步。

本轮没有改变识别模型，也没有宣称中文识别准确率提高。Qwen 的独立参考、时间对齐和切分边界仍待补齐；动态画面和原生声音理解也仍有缺口。

工具名仍是八个，已连接的 MCP 服务需重启才能看到 read 的新参数。基础搜索仍可自主供片，偏好推荐和持续循环保留为后续选项。
