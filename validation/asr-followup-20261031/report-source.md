# ASR 可疑原文：已定位的根因与剩余真值缺口

2026-10-31 · 真实样本 BV1Z8xA6zEpD，P1。沿用本地模型和已下载材料；本轮联网检索官方实现、技术报告和模型卡，并做同窗受控实验。

**Qwen 的“爱，”已经定位到强制语言诱发的生成退化，不应继续笼统登记为未知。Whisper 的开头英文则仍不能逐字确认，也不能直接判定为整段幻觉。** 上轮修复解决了候选如何保全与交付、空 owned text 如何表达；没有验证原文逐字准确，更没有证明全视频无人声。

两份 298–362s WAV 的 SHA-256 完全一致：一份来自旧生产任务，一份此次从原媒体按同参数重提取。音频为单声道 16kHz，数值有限且非全零。生成配置为 do_sample=false、num_beams=1。此处 token 数按解码后 raw 字符串重编码计数，不含结束符。主诊断将 max_new_tokens 从生产的 4096 收窄为 128，防止重跑长循环；**没有将 128 当作生产修复策略，也没有重新跑 4096 token 的退化窗口。**

## Qwen 的完整因果链

组件的 qwen_worker.py 和 qwen_pipeline.py 都写死 language='Chinese'。官方实现说明，指定语言会把对应语言标签和转写起始标签预填进提示，输出按纯文字处理；自动模式则保留模型产生语言标签的通路。这两种调用不是同一种提示语义。[Qwen 官方推理实现](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py)

在本片 298–362s 的完全相同输入上，自动模式结束于空结果；强制中文则生成连续重复单元，直至本次诊断上限。官方 parse_asr_output 在返回 text 前调用 detect_and_fix_repetitions，因此持续生成的长串被折叠成短短一个“爱，”。原先只保存 public text，掩盖了生成过程中的退化规模。[Qwen 官方解析与重复处理](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/utils.py)

随后 forced aligner 接收折叠后的文字，复现本地 0–0s。加上音频起点 298s，就成为原记录中的 298–298s；请求归属是 [300,360)，所以 owned text 为空。旧逻辑据此写 no_speech，上轮 rc6 已改为 alignment_unresolved 并保全候选。

**因此，对齐问题是链条的后段，前面还存在硬编码语言造成的生成退化。** 官方技术报告描述的 forced alignment 是给定音频和文本预测位置；它不是对文本内容真实存在的独立验证。[Qwen 技术报告第 3 节](https://arxiv.org/html/2601.21337v2#S3)

旧任务约 209s，本次上限 128 的强制中文生成加对齐约 11.78s，同模型常驻后的自动空结果约 0.485s。已确认循环会浪费生成开销；旧任务没有保存 raw token 流，因此不能把历史 209s 精确全部归算为 4096 token 循环，更不能把这些常驻计时当作完整冷启动延迟。

## Whisper 为什么还不能逐字定案

Whisper 默认跳过规则综合 no_speech_prob 和 avg_logprob。本例虽然前者高于 0.6，但后者约 -0.662，高于 -1.0，因此代码继续保留文字。这符合实现，不是工具忘了设置开关。[faster-whisper 官方源码](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)

本次开头的 VAD 选中约 1.456–2.768s 和 6–10.16s，恰好覆盖旧的可疑段。Qwen 也在开头反复得到英文候选；例如对同一处，Whisper 给出 nobody，而 Qwen 认为是 body。另有关键否定词分歧。**更像英语人声/背景音乐中的词被不稳定识别，是目前的推断；尚不能确认逐字歌词、声音来源或是否为作者口播。** 不应把这种推断升格成听过原声的结论。

OpenAI 模型卡承认 Whisper 可能生成音频中没有的文字，也可能重复，但这只是一般风险，不足以证明本例每一段都属于幻觉。[Whisper 官方模型卡](https://github.com/openai/whisper/blob/main/model-card.md#performance-and-limitations)

本轮确实尝试将本地开头片段交给宿主音频通道；通道明确返回不支持音频输入。因此没有声称完成直接听辨。ASR 一致、VAD 命中和波形非零都不能代替逐字真值。开头原始 12s 片段保存在本机核查目录，仍可供有音频能力的宿主或人工核对；未调用 Gemini 或其他外部音频识别服务。

## 产品登记与修复方向

VR-ASR-20261031-09 细分为两个事实：Qwen 的强制语言退化及后处理遮蔽已有受控证据；Whisper 开头逐字文本仍缺独立听辨真值。二者不再合并为“未知无人声问题”。

相应修复方向是让 Qwen 默认使用自动语言识别，显式语言选择才强制；保留生成长度、是否触顶和重复折叠诊断。更改解码策略时需要更新 profile 身份，保留旧固定中文轨道及其校对的读取路径。它不需要换引擎或换云服务。不能用“把所有低置信段删除”“把 token 上限压成 128”或“把对齐到 0 的字硬挪进区间”代替修复。

本轮是继续根因调查，未改变已安装的解码策略、ASR 原缓存、校对记录或续期行为。原始实验、版本与对应文件在本地 summary.json 指向的证据目录；产品文档仅保留可评审结论。
