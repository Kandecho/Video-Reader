## D 完整测试改变了文字校验的实现

真实 ASR 把“项目意识”识别成了“项目历史”。21.170 和 21.570 秒的画面均可读到“项目意识”。组件现在返回这一差异、两张原图和 OCR 行，Agent 可以据此核对。

整片测试又发现，稳定且高置信的 OCR 也会出错：把 MBTI 漏成 MBT，把“于”读成“干”。因此已撤掉自动覆盖原文字的实现。

```flow
原始字幕或ASR -> 保留原文: 始终可追溯
本地视频帧 -> OCR证据: 含时间戳和图片
保留原文 -> Agent核对
OCR证据 -> Agent核对
Agent核对 -> 带证据的回答
```

无字幕视频的 153 段均经过比较。12 段找到近似一致文案，15 段发现高置信差异。3 段有低置信差异，123 段未能建立整行对应。这些计数不是准确率。繁简体、换行、长句和画面切换都会影响对应。

“UR 自选／随机”的 AI 字幕错误仍未被整行比较自动定位。OCR 图和行证据已可用；画面公告及黄色字幕显示“随机”。不能声称此类冲突已普遍自动解决。

## E 阅读策略按完整行为优化

整片讨论要求先读取全长语音，消费全部文字分页。再沿时间线读取分段画面，补看重要冲突、动画和句子过渡。概览用于定位，不能代替整片阅读。

无字幕视频本轮实际完成：153 段语音、3 页文字、11 页画面，共 63 帧；另查看 623 和 625 秒的片尾两帧。Agent 已实际查看 8 张联系表里的全部画面，并核对关键冲突原图。

| 流程环节 | 实测工具耗时 | 含义 |
|---|---|---|
| 全长 ASR | 467.510 秒 | 实际解码整个音轨 |
| 153 段首次画面对照 | 234.543 秒 | 为语音段提取并 OCR 实际视频帧 |
| 画面对照及分段取帧合计 | 290.650 秒 | 不含 ASR 和 Agent 阅读、回复时间 |
| 同材料全部工具步骤复用 | 4.333 秒 | 复用 ASR、OCR 和帧缓存，不重新识别 |

部分验证并行使用 CPU，这些是现场计时，不是标准性能基准。后续追问复用会话和识别结果。语音处理完整、分页读完、视觉连续覆盖，分别记录；本轮没有连续逐帧观看全部运动。

采样和分段仍是设备、上下文、成本的取舍。视频直接作为原始材料交给 Agent，笔记不是必经步骤。

## F 尚未解决的基础问题

专业词和长句识别仍有明显错误，例如“主体／猪蹄”“移情／疫情”。原始 ASR 的词概率可能仍然很高，不能只靠置信度找错。

长句有时覆盖二十多秒，和画面中的多行正文难以直接对齐。逐段中点检查也可能错过短暂出现的文案。中央正文仍需结合实际画面理解。

当前动画检查只处理有限的文字字段。更一般的场景转移、动作和音效仍未解决。下一项基础改进应优先做中文术语识别、词级切句和画面段落对齐。

本机能发现 RTX 5060，但实际 CUDA 解码缺少 cublas64_12.dll。本轮如实使用 CPU，没有声明 GPU 可用，也没有额外安装 CUDA 环境。完整长时转写通过 CLI 会话验证；其他 MCP 宿主的长时超时与取消行为未做实机验收。
