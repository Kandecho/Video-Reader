## A 已完成：把已有成果接入日常调用

Qwen 不再只在实验脚本里。日常转写、返读和校对支持 `source=qwen`。

| 选择 | 行为 |
|---|---|
| `auto` | 仍优先字幕；没有字幕时用 Whisper |
| `asr` | 仍明确选择 Whisper |
| `qwen` | 显式选择本地中文 Qwen 与字词对齐 |

两套引擎的原文、缓存和校对独立。返读不启动新转写。完成的区间逐段保存，中断后补缺。Qwen 默认不注入标题提示，也不自动换引擎或上传媒体。

工具仍为八个。正式版本已升至 0.6.2，现有 MCP 服务需重启以载入新代码。

## B 小验收：接入成立，疑点不掩盖

108 项回归测试通过。真实 MCP 的转写、返读与校对预览来源一致。

| 缓存素材 | 源时长 | 解码与对齐耗时 | 实际结果 |
|---|---:|---:|---|
| 疫情科普 | 93.1 秒 | 37.0 秒 | 14 段；60 秒接缝保留疑点 |
| 烹饪教程 | 186.7 秒 | 92.3 秒 | 39 段，跨两页；保留字词时间 |
| 游戏素材 | 84.1 秒 | 27.4 秒 | 仅一个零时长“嗯”；不算有效人声 |

游戏素材的旧 Whisper 结果是无语音。Qwen 的“嗯”保留时间异常标记，不能拿它证明听到了人声。这也是保持 Qwen 可选、不替换默认引擎的理由。

耗时含每窗进程与模型加载，不含下载和宿主校对。所有源区间均处理过，不代表识别无漏字。三份正式会话和用户配置未变；验收写隔离副本。

这不是新的独立准确率测试，也没有将全片标记为已校对。模型词时不是人工真值，80ms 也不是精度承诺。

## C 这里停止扩张，后续由真实问题驱动

| 范围 | 本阶段取舍 |
|---|---|
| 常见讲解、课程、访谈 | 转写、相关画面、时间引用、校对留痕 |
| 动态细节 | 先用已有局部密集取帧补看，不开发新时序模型 |
| 音乐、音效、语气 | 明示未直接理解，不全面开发原声模型 |
| 精细研究证明 | 不建大规模盲稿或逐字人工时间标注集 |

对齐的是成熟阅读工具的能力范围，不是宣称准确率已经相同。现在收口，进入日常使用。只有具体任务频繁受阻时，再评估专项投入。
