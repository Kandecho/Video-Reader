# 诊断修复：从空材料与模糊状态到可消费证据

2026-10-31 · 核心 0.10.0rc6 / 薄插件 0.5.5。按用户要求，**续期不验证、不修改**。本轮以独立诊断作为定位线索，结合源码、历史失败记录、真实请求和原生 MCP/CLI 复验实施修复。

**已修复组件内可证实的四类缺陷，并补修回归暴露的状态读写竞态。** 外部网络为什么偶发断连、可疑语音究竟说了什么，现有证据不足以给出确定结论。

## 原因、修改和验证

| 问题 | 核实的原因 | 修复后的行为 |
|---|---|---|
| 预览 0 帧 | HTTP/API 成功响应含空 index，组件先缓存成功、后发现无法取帧，坏结果可持续一天 | 时间索引、图格、图片引用在缓存写入前验证；在线旁路旧坏缓存，同账号有界重取；离线保留缺口 |
| Whisper 可疑文字被平铺为普通文本 | 解码器允许高 no_speech_prob 但 logprob 达标的结果；原有 suspect 标记没有在阅读层充分表达 | 保留原文/段 ID，阅读、证据、导出显示 unverified_candidate；不凭低置信一刀切删除、不改解码阈值 |
| Qwen 空结果误作无人声 | 原始“爱，”对齐在 298s 且零时长，被排除在 300–360s 归属区间外；空 owned text 被当作 no_speech | alignment_unresolved，返回 raw_text、输入/归属范围与原始对齐；处理覆盖完整，校对完成为 false |
| open 间歇失败缺少恢复线索 | 历史失败发生在 yt-dlp 初始网页元数据获取，分别为 timeout / remote closed；无法确认具体外部网络根因 | 仅明确瞬时网页错误恢复一次，保留阶段和 attempts；同账号/预算/暂停，下载前重查 CID，限制错误不重试 |
| 首包没有可用图文 | 完整 OCR/逐词证据按结构拆页，图片在后面，首个响应不代表没有视频材料 | 新大阅读先给 reading_projection 原图和可读整句，原 canonical 证据继续无损提供；部分投影不暴露会跳过内容的偏移 |
| Windows 状态偶发 PermissionError | 查询方之间有锁，但 worker 替换状态文件时不参与该锁，读/replace 会交错 | 状态读写共用短时 IO 锁，包含启动失败兜底；不占视频材料锁，不更改任务共享语义 |

## 真实视频与宿主复验

- **BV1KLxN6ZERf 原生预览**：沿用原坏缓存、同账号请求一次，获得 156 个有效索引并生成 5 帧。已实际打开带时间标识的拼图；有效缓存随后离线复用成功。没有先删除坏缓存或切换身份。
- **两份真实阅读材料**：旧首图分别在第 9/16 页，新首包均为 8 张原图、60 段可读文字。继续所有 canonical parts 后可逐字段恢复原始结果，OCR/逐词证据完整。总页数各增加一页，新增的是阅读入口；并未缩减完整材料。
- **原生 stdio MCP → 共享 job → CLI**：真实缓存 read 的首个材料包包含 8 个原生 image block 和 60 段文字，首张图片逐字节等于原文件，MCP/CLI 读取同一 snapshot。约 0.58 秒是已缓存图像且关闭本次 speech OCR 的交付验证，**不是冷处理性能结论**；既有画面 temporal 证据仍保留。
- **BV1Z8xA6zEpD 旧 ASR 缓存回放**：3 段 Whisper 仍保留且显示 unverified_candidate；旧 Qwen no_speech 缓存即时派生 alignment_unresolved，原始“爱，”及 298–298s 对齐可见。未重新运行模型，未篡改原 manifest。
- **元数据恢复**：正常默认请求头与组件请求头的同账号真实请求均成功，不能据此归因某组头部。另将第一次历史断连签名明确故障注入，第二次执行真实相同元数据命令成功，使用共享预算 3 次网络请求；没有下载媒体。该验证证明恢复链路，不伪称真实网络再次断连后恢复。
