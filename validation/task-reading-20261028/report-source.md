## B 数学讲解：绕圈怎样变成傅里叶变换

[原片：3Blue1Brown，BV1pW411J7s8](https://www.bilibili.com/video/BV1pW411J7s8/)

这段视频把傅里叶变换解释为：**用不同速度把信号绕到圆上，观察哪些速度能让它形成有方向的积累。**

- **00:50–02:40：问题从混合声音开始。** 麦克风记录总压力曲线。希望从这条曲线找出各个音调，而不是只看原来的起伏。
- **02:40–07:10：区分两个频率。** 信号本身可每秒振动三次；绕圈速度可以另选。把每个时刻的高度作为旋转向量的长度。绕圈速度与信号吻合时，向量更容易在同一方向积累，质心偏离中心。
- **07:10–10:26：为什么能拆出多种音调。** 信号垂直抬高会带来零频率分量；去掉这部分偏置便改变零频附近的峰。变换具有线性，两个信号相加后的结果等于各自结果相加。视频用 2Hz 与 3Hz 的组合展示两个峰。
- **10:40–11:50：从分析走向编辑。** 找到某个频率分量后，可以减弱它，再通过逆变换回到声音。作者在这里刻意作了简化；不能据此断言“再做一次同样变换就原样回来”。
- **12:00–15:24：把图变成公式。** 旋转因子是 `e^(-2πift)`。先用均匀采样的平均，再写成区间上的积分平均：`(1/T)∫ g(t)e^(-2πift)dt`，其中 T 是观察区间长度。
- **16:07–18:40：平均与变换不同。** 去掉 1/T 后才得到这里采用的变换积分。匹配的频率随观察时间增长更明显；相邻频率更容易相互抵消。图中画的是复数输出的实部，不能把它当成全部输出或幅值。
- **18:40 之后：扩展与结尾。** 积分范围写向负无穷到正无穷；本片没有给完整收敛证明。19:22 起为赞助与凸集边界点相加的数学题，只有题目，没有解答。20:33 后为片尾署名。

本轮修正了分块交界重复词、漏掉的句首、赞助段词句和网址，共 4 个条目。原有局部校对保留；全片补读后，两个边界截句疑点已由上下文解除。没有把英文烧录字幕本身的语法问题全部“润色”成原话。

## C 软件演示：读到能说明操作

[原片：MAW，BV1S9bZ6pEHg](https://www.bilibili.com/video/BV1S9bZ6pEHg/)

视频展示的是**自动得到初稿，再由人调整字幕**。可复述的主要操作如下：

1. 00:29 拖入视频，选择转录模型，设置热词与后处理。画面选用云端模型；“软件免费”不能直接等同于模型调用也免费。
2. 01:35 左右按 B 拆分字幕。需要合并时用 Shift 选中，再按 C；X 修剪尾部。双击文本后，Ctrl+Enter 可按文字光标拆分。
3. 02:46 的“拼接/合并字幕”窗口，本次设为 200ms 阈值、向前吸附。“吸收过短字幕”没有勾选。这里主要填补字幕之间的短空隙，不能概括成把文字都合并。
4. 03:24 延长字幕的窗口显示前延 120ms、后延 60ms。有选中项时只处理选中项，否则处理全部。作者建议把这类整体调整放到后面，并演示撤销过度调整。
5. 04:31 灰色条纹字幕表示被禁用。OCR 检出它与游戏文本重复；不是删除了原文。Alt+点击可以恢复，也可以手动禁用漏检项。
6. 05:23 起承认字词时间码也会出错。可以改用文字拆分，或关闭自动按时间码拆分。338 秒仍勾选，339.5 秒取消，341.5 秒出现拆分面板。
7. 06:16 批量替换先预览再执行；07:17 导出 SRT。频谱、跳过无声片段和布局切换帮助检查，不代替内容判断。

## D 长英文访谈：不能漏掉反对与限定

[原片：The Vergecast，arjKK7fRtSA](https://www.youtube.com/watch?v=arjKK7fRtSA)

**访谈认为，Markdown 能普及，是因为它让纯文本容易阅读，也得益于开放生态。** 主讲者 John Gruber 回顾自己的设计，Anil Dash 补充早期博客和出版生态的经验。

| 时间 | 本片的主要内容 |
|---|---|
| 00:00–04:06 | 主持人引入 Markdown；中间插入标注 2026-06-15 的新闻简报。新闻属于节目当时的内容，未拿来当现在的事实 |
| 04:06–09:43 | Gruber 讲博客写作、HTML 的麻烦，以及 Textile、Movable Type 等背景。核心取舍是让没学过语法的人也容易读懂 |
| 09:45–15:40 | 编辑者和插件生态帮助传播；嘉宾回顾分散博客和开放工具之间的协作 |
| 15:55–18:25 | 主持人称它很快普及，Gruber 明确纠正：早年增长很慢。随后谈 Stack Overflow 和 GitHub 对采用的影响 |
| 18:35–24:11 | 讨论 Markdown 编辑器与所见即所得编辑器。隐藏符号可能重新带来格式边界难处理的问题 |
| 24:11–26:58 | 普通人可以学，但不应被强迫学。Gruber 更把 Markdown 看作一套写纯文本的约定，也接受不同变体 |
| 27:00–31:13 | 讨论 AI 为什么常用 Markdown，以及个人创造怎样推动开放网络。嘉宾认为 LLM 更擅长输出 Markdown，而非 JSON；这是他的判断，不是本轮测量结果 |
| 31:13–结尾 | 道谢、节目联系方式、订阅说明、制作署名与告别 |

**18:55 左右是本轮发现的实质错误。** 主持人把 Apple Notes 的支持说成直接写 Markdown；嘉宾接着否定这一点，认为它也不该成为这种编辑器。自动字幕漏掉了否定。1120–1146 秒局部重听恢复了“并不”，后面关于复制和导出的讨论也支持这个区分。

三个滚动字幕条目保存了同一句话的修正。原始自动字幕没有被覆盖。文件名 `claw.md` 仍保留疑点，不靠常识改成确定转录。

这条视频也暴露读取成本问题：1903 条字幕中有 950 条约 10ms 的过渡条目，全文约 10.4 万字符，包含大量滚动重复。这次完整读过了；后续可以减少重复展示，但必须保留原始条目、时间和回查关系。

## E Scroll 比较：自动化应当停在哪里

[第二片：《为什么一键生成，永远是伪需求？》](https://www.bilibili.com/video/BV1z9n86gEWS/)

**两片共同支持“把目标和判断留给人，把目标明确的重复处理交给工具”。** MAW 给出可操作的例子；短片解释为什么一句话无法表达所有偏好。

短片先说明一句指令背后仍藏着时长、工具、风格、镜头和音乐等决定。固定提示词只是替用户预先作了一部分决定，未必符合不同用户。它再谈市场验证与创作者品味。**02:39–02:45，作者明确承认接受默认方案或只要初稿时，一键生成可能是真需求。** 这项限定必须连同标题一起读。

| 比较点 | “一键生成”短片 | MAW 演示 | 本次判断 |
|---|---|---|---|
| 用户需要先决定什么 | 目标、呈现方式和偏好不能凭一句话保证猜中 | 用户选模型、热词、处理规则，并检查结果 | 默认可以帮助启动，重要选择要能表达和更改 |
| 自动化能做到哪一步 | 结尾接受默认方案与初稿用途 | 自动转录后仍有拆句、校字和时间调整 | 初稿自动化有价值，完成标准需按任务判断 |
| 批量操作是否有价值 | 没有排除所有局部自动化 | 200ms 拼接、前后延长、替换都能批量做 | 目标和范围清楚的步骤适合一键执行 |
| 出错后怎样接管 | 主要讨论决策与品味，没有给操作方案 | 撤销、Alt恢复、手动拆分、替换预览 | “能修正”应当是工作流的一部分 |
| 证据能支持多强的结论 | 论述与个人例子为主 | 屏幕演示具体行为 | 都不能证明任何产品或人群必然如此 |

短片的数字不能直接当成测量结论。01:12 的“1%”是说明组合选择的示意；01:49 展示 CTR 数字，但本片未交代可核验的实验过程。02:12 旁白称“42% 内容无法蒸馏”，而下图把 26.5%、42% 覆盖率、约43% 等口径分开。**这张截图不能支持“42% 内容永远无法交给模型”的结论。**

![02:23.5 原生裁图：截图区分多种比例与估算口径，需要和旁白一起核对](D:/IA/apps/video-reader/data/cache/v_d138ef2a6f645451c30be582/frames/4d934e3ee8af9a673ed98e5e/region.jpg)

对 Reader 的启发是：继续自动完成获取、定位、分页和复用；宿主对照具体问题判断证据是否够用。Scroll 比较时应先保留各片限定，再综合判断。不能只比较标题，或混淆论据来自哪一片。

该批次每页实际读取后才确认；未确认页重放一致。两片均完成交付，没有失败项。另保存了短片 7 处术语修正和数字口径疑点。批次状态只证明交付，以上比较才是本次阅读产物。

| 事项 | 本轮结果 |

| 已有能力保全 | 本轮只增加材料、修订与文档；生产代码、模型、日推规则未修改 |

下一步优先补**可追溯的连续字幕阅读视图**，减少滚动字幕和分页重复。应从本次 YouTube 与 Scroll 样本验证，不能按长度删句。它是这轮新确认的待办，并非已经实现。

漏否定、数字口径冲突和短暂按钮变化，本轮都能用现有能力补证。需要加强宿主的触发判断，而不是一遇到疑点就重读全片或增设另一个模型。是否需要组件提示，应由同类失败复现决定。

独立聊天能否顺利接手讨论，还需要你的用户侧体验。当前已证明进程和记录可以恢复；我没有把它扩大成“另一个聊天已经理解全文”。干净机器的可选模型安装和广泛准确率，仍未因这些案例而通过。YouTube 长期登录态维持是当前缺失的能力，不能由当次 Cookie 可用推定。
