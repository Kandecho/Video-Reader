# Video Reader 架构问题修复

**冻结审计中已确认、可在既定产品边界内处理的修复已完成。** 三个职责域继续保留，没有新增模型、消费策略、渠道或服务。非阻塞未知和后续能力仍在路线中登记。

## A 冻结基线

基线为[完整架构审计及综合结论](../architecture-audit-20261108/README.md)。报告与旧验证保持原样，后续修改结果记录在这里；当前待办状态在[路线](../../planning/roadmap-20261021-source.md#e-冻结架构基线修复)维护。

冻结前源码固定在[修复前提交 `13565e8`](https://github.com/Kandecho/Video-Reader/tree/13565e85a64e8fb8e9495262daa9b983e7ffbe69)。本地保留 162 文件的原始归档及逐文件指纹；ZIP、原始日志和本地 HTML 不纳入公开源码。

## B 本批修复结果

| 修复 | 现在的行为 |
|---|---|
| 联网管控与认证 | 搜索、热门及下载共用预算、暂停和间隔规则；保留匿名、用户 Cookie 和托管登录。账号标识与请求上下文由认证模块提供 |
| 平台材料协议 | 完整获取与预览共用字幕翻译；评论基础翻译及弹幕分段信息集中处理，保留样本、分页、分 P、账号和失败覆盖差异 |
| 音频与选帧缓存 | 音频只缓存测量，续读位置根据本次请求生成；adaptive 绑定实际使用的原始语音与选帧政策，无关校对或均匀取帧不受影响 |
| 识别与历史材料 | 模型实际文件状态、运行时元数据和政策参与结果身份。新解码不拼旧轨；speech_profile 可选择已存轨用于读取、校对和导出，不启动解码 |
| 作业执行 | worker 核对登记时的配置与账号身份；发生漂移则明确失败，要求重载后显式请求，避免按旧配置登记、按新配置执行 |
| 图像交付 | 新快照的可读投影与后续证据页不重复附带同一源图；原始字段和 OCR／词证据无损，独立请求可再次附图 |
| 任务与个人工作流 | 调度器使用任务模块的公开运行／许可／恢复判断；任务使用 Reader 资产与活跃作业接口；推荐不扫 manifest；记忆不依赖整套 Agent 装配 |
| 宿主与入口 | 错误类别在宿主通路统一，任务执行原额度暂停和连接短重试政策。OCR 可用性与 Windows 预热归能力模块，入口不识别厂商内部实现 |
| 构建与测试 | 候选补齐六个已有运行脚本；策略一致性测试改用临时核心。源 Skill 与本地两端薄适配器 0.5.6 已同步 |

同库事务、原 run／许可／名额、检查点、暂停晚包保护、唯一结果、固定日轮首条和发送不确定账本均保留。原文、旧校对和已冻结页继续保存；新能力版本不会自动继承旧校对。

## C 验证

整合套件中 **448 项通过**，两项真实 stdio MCP 协议用例单独运行，**2 项通过**。合计 **450 个不同用例通过，0 失败、0 错误**。原先的协议待验证项已完成。

真实协议检查使用临时配置、合成视频和字幕，不调用真实模型或平台联网。它们在支持子进程握手的权限环境运行；此前沙箱握手未完成，不能据此当成产品故障。历史 Windows 原子替换原因仍单独保留。

Skill 与本地适配器版本更新后，插件、构建及策略接口的相关 **19 项复验通过**。专项检查与整合套件有重叠，不累加为额外不同用例。独立代码复核与冻结快照比较了相关生产改动，无实质发现。

[验证摘要](summary.json)记录 450 项结果、两项协议检查、入口复验及冻结基线身份。原始日志和 runner 输出保留本地；可按根目录 [CONTRIBUTING](../../CONTRIBUTING.md) 运行项目测试。

## E 实施边界

用户授权自主选择修复顺序。保留三个职责域及现有产品规则；先修正确性，再收口实际消费者依赖的接口。必要的旧轨回查与兼容接口纳入修复。新模型、新消费策略、视觉短会话、推荐变化、新渠道和新回答引用能力继续作为后续方向。

冻结前验证为 415 项通过、2 项协议用例待验证，以上结果来自修改后的新验证。没有以旧通过数量替代新实现的验证。
