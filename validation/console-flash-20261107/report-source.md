**确认我们这边的队列定时任务会造成这次闪窗。** 即使队列为空，启动检查仍会显示约 1 秒的 Windows Terminal。修复后，手动触发和 20:55 自然定时触发均未再出现窗口。

## 为什么会出现空窗口

原任务每 5 分钟直接启动 PowerShell。虽然命令包含 `-WindowStyle Hidden`，本机仍先显示了终端窗口，随后才隐藏并关闭。队列的输出都写入文件，所以看到的是空白窗口。这次复现没有收信、读片或模型调用。

```flow
每5分钟触发 -> 启动PowerShell
启动PowerShell -> 终端显示约1秒: 实际捕获
终端显示约1秒 -> 隐藏并关闭
```

这能解释用户描述的间歇闪现。<mark>本次已经复现了本组件造成的闪窗，没有据此断言电脑上所有闪窗都只有这一个来源。</mark>

## 修复改变了什么

任务改用同一 Python 安装中的 GUI 解释器，先进入无窗口启动脚本，再运行原业务入口。它通过 `CREATE_NO_WINDOW` 启动 PowerShell。微软说明该标志让控制台程序在没有控制台窗口的情况下运行。[官方说明](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)

```flow
定时任务 -> 真实GUI解释器
真实GUI解释器 -> 无窗口启动PowerShell: CREATE_NO_WINDOW
无窗口启动PowerShell -> 原收件或队列或日推脚本
```

本机虚拟环境中的 `pythonw.exe` 是控制台 shim，名称具有误导性。第一次替换后仍捕获到闪窗。读取 PE 子系统确认其值为 3，现改用同一安装中值为 2 的真实 GUI 解释器。安装脚本也检查这一点。

三个现有任务只替换了启动 Action。后台收信仍禁用；队列仍在 09:00–23:00 每 5 分钟检查；日推仍为 20:00。日志、业务入口及退出码保留，没有为验证执行收信或真实日推。

## 实际验证

| 场景 | 观测结果 |
|---|---|
| 原 PowerShell 入口，20:46:51 手动触发空队列 | 20:46:52.211 显示，20:46:53.204 隐藏，约 0.993 秒 |
| 中间方案：虚拟环境 pythonw，20:49:46 手动触发 | 仍显示窗口，不能作为修复成功 |
| 中间方案：20:50 自然定时触发 | 再次显示窗口，确认需要避开控制台 shim |
| 最终方案：20:51:15 手动触发 | 55 秒观测中，控制台窗口事件 0；队列退出码 0 |
| 最终方案：20:55 自然定时触发 | 覆盖 20:54:47–20:55:47 的 60 秒内，控制台窗口事件 0；20:55:01 正常结束，退出码 0 |
| 启动器自动检查 | 3 项通过：非零退出码与输出保留、启动失败留日志、无害替身验证日推路由 |
| 后台既有检查 | 30 项通过；修正测试夹具中的模拟时间不一致，未改业务计数逻辑 |

日推只验证共用入口和临时替身，不重跑真实投递。收件任务保持禁用。窗口监听在短时验证后结束，没有安装新的常驻监控。

本地原始事件、修复前 Action 与安装预览保存在 `data/diagnostics/console-flash-20261107/`。业务执行日志位于 `data/agent/background-task/queue/`；启动层日志位于 `data/agent/scheduler/`。
