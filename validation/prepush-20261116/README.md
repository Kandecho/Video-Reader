## 修复

- `tools/build_candidate.py`显式包含目录HTML模板、链接检查CJS及工作流说明页，保留原私有文件排除边界。
- 新分发回归从候选独立进程导入，实际执行`Catalog.build()`，防止安装目录掩盖缺失模板。
- 目录和插件测试规范化临时根路径，消除Windows目录大小写造成的3处断言误报；生产路径逻辑不变。
- 真实MCP集成测试的客户端放入独立子进程。父测试使用30秒硬超时，并只清理自己启动的进程树；内层另有请求上限和栈诊断。

早期全套卡住的栈位于Windows异步事件循环构造时的本地socketpair，发生在协程和MCP请求之前。正常权限下该集成通过；受限环境的单例现在约32秒明确失败并收尾，不再无限等待。没有修改生产网络或事件循环来规避宿主限制。

首轮完整回归在网络状态文件上遇到WinError 5，第二轮在批读状态文件上遇到同类错误。普通Windows读句柄可复现相同拒绝替换，原失败的具体句柄持有者仍未知。

处理收敛到共享`write_json`的原子replace阶段，删除了初始Budget局部包装。仅对Windows错误5/32做累计0.31秒的有界等待，重试同一个临时文件；不重放上层业务、不重复增加计数。永久或其它错误继续抛出，序列化和临时文件清理保持原逻辑。底层覆盖原子完整性与错误边界，网络层另保留计数和跨进程回归，避免复制同一套错误重试测试。
