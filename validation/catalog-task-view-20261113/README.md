# 任务与成果目录调整

适用：2026-11-13开始调查，2026-11-14完成本地实现。入口为 `data/tasks/catalog/index.html`，实现为 `reading_tasks/catalog.py` 和 `reading_tasks/catalog_view.html`。

原界面以来源视频聚合主条目，实际任务、主要成果和历史同时藏在展开层；首页先呈现留存方式、用途和批次管理字段。任务筛选实际早已存在，但命中后仍按视频展示，妨碍直接寻找“要做什么、做完没有、成果在哪”。

本次默认按独立任务显示，具体工作作标题，原视频作材料关联；成果入口前移，完整回答、原话、留存元数据、覆盖与旧版本在详情中。保留按视频查看与批次投影。主筛选改为完成情况和任务要求／去向，次要字段收进更多筛选；窄屏收紧控制区，清除筛选也收起次要字段。

状态沿用任务库枚举，“待完成”同时包含pending与paused，暂停逐项标识，取消不计完成。后半段为任意自由文本task_description，不是固定类别；历史描述通过datalist与catalog-status.description_history供选择和复用，关键词可查任意当前描述。新记录先复用相似去向的历史措辞，含义不同可新写；不做自动语义合并。task_goal与task_description分别绑定当时正式任务，任务改变后旧值失效，旧措辞保留作历史建议。旧done无登记成果或只对应改要求前的成果时显示明确警告，不改写数据库状态。

## 数据保全

人工补注42项自由描述，分类依据和原要求快照在 `classification-proposal.json`，实际应用脚本为 `apply-descriptions.py`。未确认要求的取消项留空；同样的处理去向复用同一措辞。日语归纳目标纠正为整片翻译仍暂停、54秒校对小试已完成，避免把局部试验当作整体待办。

`data-verification.json`核对原42任务的状态、正式要求、创建／更新时间、原话、消息和90次成果逐项不变。原metadata备份为 `metadata-before.json`。当前38个有成果来源、39 done／2 paused／1 cancelled，0缺失文件；5份历史文件变化标记继续保留。未重读、未新增任务或成果，未发送或恢复后台。

快照新增全队列tasks，旧videos与旧统计继续只含有登记成果的条目，新增total_tasks/without_results/total_task_states用于全任务口径。无成果任务不会成为“已读视频”。新任务及结果的提交和目录刷新分开，刷新失败保留已提交事实并报告错误。

普通queue-add新增任务提交后刷新；Inbox同步每页确实新增任务后刷新，后续页失败也不漏已提交待办；Inbox手动入队在来源消息关联提交后刷新。重复入队不重复刷新。此改动没有启用或实际运行收件。
