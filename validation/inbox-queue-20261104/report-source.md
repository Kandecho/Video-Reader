## 分页故障与修正

最初实现误把 begin_seqno 当作旧消息的上界，隔离模拟也沿用了这个假设。真实第二页未向旧消息推进，组件按预期停止并保留首批 8 条来信与游标，没有跳过范围、清空历史或创建错误待办。

随后对同一授权会话只读核对两个参数：begin_seqno 返回边界后的较新消息，end_seqno 返回边界前的较旧消息。已改为 end_seqno，并让测试明确断言该参数；空会话 messages=null / has_more=0 也按可结束的空历史处理。当前同步从原检查点继续，无需重置启用时间或数据库。

本批共有 10 次授权会话 GET：初始格式核对 1、首次分段验收 2、边界方向核对 2、成功续接/重放验收 5。均使用组件原预算和登录，无 POST、会话列表扫描或视频请求。成功验收数据在本目录本地 live-result.json，探测原文在 .test-work；私人原文和运行脚本不纳入公开源码。

接口字段参照已有项目调用及客户端[私信实现](https://github.com/PastGone/bilibili_go/blob/master/message.go)核对；消息类型及上下界参照原始[接口观察记录](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/message/private_msg.md#查询私信消息记录)和[消息对象记录](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/message/private_msg_content.md)查阅。分页方向最终以本次同账号真实返回为准。

## 数据与实现边界

- 复用同一 SQLite，新增 inbox_feeds、inbox_messages、queue_items、queue_links、queue_events、queue_meta；按组件账号隔离。每页消息、自动入队和续传游标同事务提交。
- 新消息缺口扫描和旧历史补入分开；保留 live watermark、待补范围和旧历史上界。网络失败后保留已提交页；下次显式同步继续。新消息到达不必等待全部旧历史补完。
- 同消息重放幂等，独立消息的相同活动任务关联同一项；不同附言/任务或明确 new_task 保留独立任务。分 P 保留，短链不展开，AV/BV 别名不假装已归并。
- 原消息 JSON、来源、时间、序列、解析状态和修订保全；撤回/异常来源不会静默删除已有任务。任务 note、状态和排序的变更保留前后值及原因。
- 消息按原序列倒序；历史补入后新旧顺序仍正确。队列列表绑定排序修订，变动后明确要求重新查询；不可变事件历史采用游标续读。
- 查询只读账号身份与本地数据，不构造网络 Platform 或验证登录。只有显式 sync 构造只读网络通路；收件内容及 task 一律作为材料，不执行其中的命令。
- done 是明确人工标记，Reader 完成和宿主观察仍为 not_inferred。没有 worker、processing、自动读取、云端回退或结果生成。
